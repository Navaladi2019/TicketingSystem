# ADR-006 amendment A2: the count gets a time budget

> **Status: ACCEPTED, rev 2.1** (2026-11-21). The Solution Architect gave the verdict after the Technical Architect's and the Security & Multi-Tenancy Reviewer's rev 2 critiques. Every item was taken as proposed. Nothing was contested, so no CTO tie-break was needed. Rev 2 replaced rev 0/1's statement-shape design, per the CTO's ruling (C2).
>
> **Rev 2.1 changelog (rev 2 critiques).**
> - **TA (2a), (3a)**, the Technical Architect's conditions for acceptance: A2-8 gains the host rule for the budget measurement and spike S-A2-cancel.
> - **TA 2:** both paths end with `ROLLBACK TO SAVEPOINT`. The count writes nothing, so no restore is needed and the overhead is 2 round trips, not 4. A2-2 keeps 200 ms and the freed 6 ms as margin.
> - **TA 3:** the budget is `statement_timeout`, never a context deadline (A2-3).
> - **TA 6:** A2-2 uses the pointwise bound instead of "adding p95s".
> - **TA 8, 9, 11:** the count is one `UNION ALL` statement; the timeout is `min(CountBudget, q.Timeout)`; the page now runs before the count; the budget also covers legacy-scan data filters, and lists with no data filter keep today's count.
> - **TA 12, 13:** the UI keeps the best-known total across pages (A2-1), and A2-7 says the post-backfill alert is the R-a signal, not an outage.
> - **Security:** A2-6 (c) is reworded with the reviewer's text. A2-8 gains three tests: the tenant context survives the rollback, nothing leaks onto the pooled connection, and the delay hook is test-only. The register row gains the reviewer's sentence.
>
> **Rev 2 changelog.**
> - **Removed:** rev 1's pre-count, the visible-set guard, the 3-field cap, `ListQuery.CountWhere`, the forced probe and R13. D7's side-table readers go back to the single `EXISTS`, and the D7 static test is unchanged.
> - **Added:** a count budget (A2-2, A2-3), the `total_state` contract (A2-1), the first-page shortcut (A2-4), the isolation argument (A2-6) and a new merge gate (A2-8).
>
> **Why rev 1 failed** (A2-11, PR #812). S-A2-skew passed; S-A2-anti and S-A2-multi failed. Two plans are possible for a broad value under a narrowing ACL. The hash join is right when the value sits on records the caller can't see. The per-record probe is right when it sits on the caller's own records. What decides between them is how the value correlates with the visible set, and nothing can know that before doing the work. In the 6% anti-correlated cell the probe added 341-557 ms; no guard limit `K` fixed it, and R13's step measured 230-470 ms. A bounded cost is the only fix that holds for every band and every plan (CTO).
>
> **Invariants source.** The project description defines no invariants, so the invariant check is incomplete. Checked against [[ADR-001-platform-blueprint]] §1, I1-I9, as ADR-006 and A1 are.

## In plain words

A list request returns one page of records plus `total`, the number of matching records the user may read, counted up to 1,000. The page is fast in every case we measured. The count is not. When the user's row ACL hides most records and the filter matches a large share of the type, PostgreSQL can count in a way that reads every matching side row in the tenant, including rows the user can't see. How long that takes depends on vacuum state, on other tenants' edits, and on how the value is spread across records. We tried four ways to make PostgreSQL always pick the fast plan. Each one moved the slowness to a different case.

So we stop trying to choose the plan, and limit how long the count may run instead. The count gets 200 ms. If it finishes, the response says `total_state: exact` or `capped`, as today. If not, the page is still returned, `total` is `null` and `total_state` is `unknown`. The UI then shows "50+" (the matches it already has) rather than a number. A list in this band can no longer take 0.6-1 s because of its count.

## Decisions

| # | Decision |
|---|---|
| **A2-1** | **Contract (CTO condition 1).** `RecordList` gains a required field, `total_state: exact \| capped \| unknown`. `total` stays required but becomes `integer \| null`: an integer for `exact` (0-1,000) and `capped` (1,000), and **`null` for `unknown`, never 0**. A Go zero value can't be mistaken for a real total. `total_capped` stays, true exactly when `total_state = capped`, and is deprecated in favour of `total_state`. The OpenAPI sources (`api/paths/records.yaml`, the bundle), the generated server and SDK types, and the UI ship in the same story. The UI shows `exact` as the number, `capped` as "1,000+", and `unknown` as "N+", where N is the number of matches already listed (page × limit), or "many" when that isn't known. A client must never render `unknown` as 0. The count runs on every keyset page, so `total_state` can change between pages; the UI keeps the best-known total for the result set (an earlier `exact` or `capped` is not replaced by a later `unknown`). |
| **A2-2** | **The budget (CTO condition 2): `CountBudget = 200 ms`**, a named constant in `internal/records/store`, not a tenant setting. Sizing for band (ii) (≥ 40% with a narrowing ACL, limit 350 ms p95): **350 − 94 − 6 − 35 = 215, rounded down to 200 ms.** The 94 ms is the non-count part of the request at p95. It is the list handler's p95 on the idle reference machine, 72.5-73.5 ms (P3-36, quoted in `docs/data/field-index-measured.md`), plus the band (ii) page statement's worst server time, 20.6 ms (run 5; TICK-992 measured 4-14 ms). The 94 ms is conservative: P3-36's control already includes a records-only count. The 6 ms covers two extra round trips (`SAVEPOINT` + `SET LOCAL` sent as one no-argument `Exec`, then `ROLLBACK TO`) at P3-36's 3 ms transport gate. The 35 ms is the 10% provisional-pass margin of A1-8, and rounding down leaves another 15 ms. **Why the sum bounds p95:** the count phase is at most `CountBudget` (plus the cancel overshoot, A2-8 (3a)) on **every** request, so latency ≤ non-count + 200 + overhead holds pointwise. Therefore p95(latency) ≤ p95(non-count) + 200 + overhead. A2-8 (2) measures the 94 ms directly, under the host rule of A2-8 (2a); if it is higher, the formula is rerun, with a floor of 100 ms. If the floor is reached, the decision goes back to the CTO. |
| **A2-3** | **Mechanism (CTO condition 4).** The handler runs the **page first** and reads its rows to the end (`rows.Close()`) before the count, because pgx allows one active query per connection. Today `List` runs the count first, so this is a reorder. It then sends `SAVEPOINT list_count; SET LOCAL statement_timeout = '<ms>'` as one no-argument `Exec` (pgx uses the simple protocol, which accepts several statements). `<ms>` is `min(CountBudget, q.Timeout)`, the latter when the list already runs under `DataFilterTimeout`. It runs the existing capped count, which is **one statement** (`CountStatement` joins ACL branches with `UNION ALL`), so one `statement_timeout` bounds the whole count phase. **Both paths end with `ROLLBACK TO SAVEPOINT list_count`.** The count writes nothing, and the rollback also undoes the `SET LOCAL`; `RELEASE` would not. On success the handler uses the count. On SQLSTATE `57014` with the request context still live, it answers with the page, `total: null` and `total_state: unknown`. **The budget is `statement_timeout`, never a context deadline:** `timedOut` keeps a 57014 as an error once `ctx.Err() != nil`, so a Go deadline would turn every budget hit into a 5xx. That would also give a second oracle, a 5xx versus a 200. Request cancellation stays an error. A page-statement timeout still returns `filter_too_expensive`. The budget covers every list with a data filter, indexed or legacy scan. Lists with no data filter keep today's count, since it reads no side table. |
| **A2-4** | **First-page shortcut.** If the page statement is on the first page (no keyset) and returns at most `limit` rows (it fetches `limit + 1`), every match is on the page, so `total = len(items)` and `total_state = exact`, with no count statement. This is exact by construction. It removes the count for every short result, including the "no match" and "value only on hidden records" answers, which are now always `exact` (A2-6). |
| **A2-5** | **D7 reads, from this amendment on:** "… `total` is the existing capped count (1,001) of that same statement, run under the count budget (A2). It is `unknown` when that budget runs out, and it is taken from the page when the first page is short. There is no separate count, facet or progress query on a side table. A static test enforces this." The single `EXISTS` shape, the row-ACL compilation, the 1,001 cap and the D7 static test are unchanged. |
| **A2-6** | **Isolation (CTO condition 3, for the Security & Multi-Tenancy Reviewer).** `unknown` is a function of how long the count takes, and that time partly depends on rows the caller can't read. The hash join reads every side row of the value in the tenant. Pooled statistics and the shared visibility map (other tenants' edits) can change the plan. The claim: **this bit reveals no more than the timing channel the response already has, and less in two respects.** (a) It is a threshold of a quantity the caller already observes: the count's duration is part of the request's latency today, and repeated requests average away network noise, so the bit only lowers the attacker's cost of a reading they could already make. (b) The budget caps the timing channel. Above 200 ms, every count looks the same, where today it leaks continuously up to about 1 s. (c) A2-4 makes the single-value existence probe deterministic (`exact 0`, no count). A filter padded with readable matches still runs the count, whose duration reflects hidden side rows in aggregate, as in (a) (Security's wording). (d) Load also flips the bit, so it is noisy, as latency is. There is no new statement, no ACL-free read and no new label. **Security's ruling (APPROVE):** (a) holds. The threshold is on time, which moves with load and plan. One hidden side row costs about a microsecond, far below the run-to-run spread, so a record-level differencing attack isn't practical, unlike rev 1's exact row-count threshold. Cross-tenant, the count reads no row of another tenant (the value indexes lead with `tenant_id`, RLS is forced). Its only dependence on tenant B is the noisy-neighbour signal every shared-database latency carries. Rated Info. |
| **A2-7** | **Observability (CTO condition 4).** `observeIndexedList` gains exactly one label, `total_state`, so its labels are `acl` × `selectivity_band` × `total_state`. No tenant, field, value or count goes in a label, log or span attribute. An alert, owned by the Technical Lead next to A1-4's, fires when more than 5% of data-filter lists in 1 h return `unknown`. That is the signal to look at (b) or the page half. After a backfill, or after edits that leave a poor visibility map, broad ACL counts take 100-490 ms single-client, so this alert is expected to fire until autovacuum runs. That is the R-a signal working as intended, not an outage, and the runbook says so. |
| **A2-8** | **Merge gate for the C2 compiler PR**, on top of review and green CI. (1) A2 is ACCEPTED. (2) **Budget check:** on the kit's fresh stack, the non-count p95 of the band (ii) cell (page plus handler, with the count skipped by a test hook) is ≤ 94 ms, or A2-2's formula is rerun with the measured number. (2a) **Host rule:** it is measured with D13's 8 clients for 15 s, and counts only on a host that passes P3-36's gates (transport ≤ 3 ms, and the no-filter control within 1.1× of 73 ms). Otherwise the result is inconclusive and is rerun, not fed into the formula. (3) **Failure path:** an injected count delay (a test-only hook that adds `pg_sleep` to the count) gives HTTP 200 with the full page, `total: null` and `total_state: unknown`, never a 5xx. The same transaction then runs a further statement successfully. `statement_timeout` is back to its earlier value. Request-context cancellation is still an error. The count of a branched ACL is still one statement under one timeout. (3a) **Spike S-A2-cancel**, on the real slow plan, since `pg_sleep` checks for interrupts constantly and so cannot show the overshoot. Fixture: PR #812's a6 anti-correlated count in visibility-map state `none`, or any value whose count today exceeds the budget. Run it 100 times single-client and once under 8 clients, with `CountBudget` in force. *Pass:* the count phase's wall time is ≤ `CountBudget` + 15 ms at p99; every response is 200 with `unknown`; the transaction runs a further statement; `pg_stat_database.temp_files` / `temp_bytes` show no leak afterwards. *Fail:* re-derive A2-2 with the measured overshoot as an extra term. This is not a design change. (3b) **Tenant context survives the rollback:** after a forced 57014 and `ROLLBACK TO SAVEPOINT`, the same transaction still has `current_setting('app.tenant_id')` = A, and a following statement on `records` returns only tenant A's rows. (3c) **No leak onto the pooled connection:** after an `unknown` response, the next transaction on the same pooled connection, possibly for another tenant, has the default `statement_timeout` and no `app.tenant_id` (the `alloc_integration_test` pattern). (3d) **The delay hook is test-only:** the `pg_sleep` injection is reachable only through an `export_test.go` option, never through a request, header or env var, and a static or build-tag test asserts that. (4) **Shortcut:** a short first page runs zero count statements (statement hook), and a full first page runs one. (5) **Carried over from PR #812** (CTO condition 5): no count statement on a refused request (400 masked, 422 backfilling, 400 invalid value, 400 invalid or masked cursor); tenant B's 50k side rows, including rows forged under A's field id, never change tenant A's `total` or items; an ACL-denied broad value gives the same status, items, `total`, `total_state` and body keys as a value that exists nowhere; and the metric-label assertion of A2-7. Each carried-over test also asserts `total_state`. (6) **Contract:** OpenAPI lint plus a round-trip test showing `unknown` serializes as `"total": null`, and a UI test for "1,000+" and "N+". (7) **TICK-1022's acceptance:** the S21 kit's ≥ 40% ACL cell is ≤ 350 ms p95 on **two** fresh stacks in a row, with `total_state` in `{capped, unknown}`. The kit records the share of `unknown`. |
| **A2-9** | **Budgets and bands.** D13 as amended by A1 doesn't change. A2 makes band (ii) hold by construction, not by plan choice. A 200 ms count budget doesn't help the 150 ms bands, which keep their existing scores. The page half is not covered. The 2% page (TICK-992), and the anti-correlated page walk measured on PR #812 (a6 page 96-335 ms server time, a50 2.2-3.4 s), stay on the R-a track (CTO). |

**Not changed:** RLS, the row-ACL compilation, the masks (D6, R9/CI-2b), the 1,001 cap, the page statement, D13 numbers, R-a, R-b, R8, R9, R11, R12. I1-I4 and I6-I9 aren't touched. There is no grant, no role, no write path and no workflow, and the `SET LOCAL statement_timeout` mechanism already exists (`boundDataFilter`).

## Competitive Gate (ADR-008)

**Result:** PASS. X3 (speed) improves: a band (ii) list can no longer exceed 350 ms because of its count. CP-FW-01 ("slow loading at high ticket volume") is reduced. The cost is a less exact `total` under load, which is shown honestly as "N+". No new vendor, cost or component.
