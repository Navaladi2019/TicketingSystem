### Proposed wording for the amended CI-6 (for the Solution Architect's erratum)
> `ReadBranches` on a converted format-1 policy produces the same branch count as `main`, and the same SQL text and bind arguments, up to two rewrites: (a) a constant `true` conjunct is removed; (b) a `where` condition with `caller: self` renders as `= $n::uuid` with a `uuid.UUID` argument, where `main` rendered `= ANY($n::uuid[])` with a one-element array. Rewrite (b) can change the planner's index choice within a branch. When it sits beside a subject equality on the same column, both now form one equivalence class instead of being double-counted. Measured as neutral or faster on 800k records (TICK-993). The golden test compares text after normalizing (a) and (b), not by skipping cases.

### Proposed test change (for the PR #765 engineer; replaces the `ci6TextPending` skip)
Before comparing, normalize main's golden in place of the skip:
- (a) replace `(true AND ` with `((`. This keeps the parenthesis count correct.
- (b) for the argument that came from `caller: self`, rewrite `= ANY($n::uuid[])` to `= $n::uuid`, and rewrite the argument string from `[]string [<id>]` to `uuid.UUID <id>`.

Rewrite (b) must target only the `caller: self` argument, for example by limiting it to a one-element array whose value equals the caller's `PrincipalID`. A blind rewrite of every one-element `ANY` would hide a real regression of an `in` list to a scalar. The engineer chooses the mechanism. I checked the two rewrites by hand against the diff of the 8 cases above; they have not been run as code.

### Spike report
- **Hypothesis:** neither difference changes the chosen plan or index use for the seeded stack's ACLs. **Pass:** identical plan shape, main text vs PR text, for every divergent case, in both custom and generic plans. **Result:** passes for the seeded ACLs, the onboard default (fold) and D-3-27 (identical text). It **fails as worded** for `caller: self` (`every_subject` fixture only), where index use changes for the better.
- **Setup:** throwaway `postgres:16.10` (the pinned image), `shared_buffers=1GB`, with schema and roles copied by `pg_dump --schema-only` from the running `nava-s18` stack, so the indexes and RLS are exactly the stack's. Statements are built with `pipeline.PageStatement` / `CountStatement` (what `List` runs), `Where = true`, `LIMIT 26`, descending sort, run as `nava_app` with `app.tenant_id` set (RLS active). Data: 800,000 records in 1 tenant and 1 definition; requester spread over 20k principals and assignee over 500 (20% NULL), 20 groups, 5 states; 60,000 `record_shares`; `VACUUM ANALYZE`. Skewed rerun as described in finding 2. Host: Windows 11, Docker VM 16 CPUs / 24 GiB, Go 1.26.11, pgx v5.11.0. `TestFieldIndexPerf800k` from another task was running on the same host, so treat absolute ms as contended; only the main-vs-PR differences carry meaning.
- **Limits:** the data is synthetic, because the seeded stack itself has 0–22 records, which only ever gives seq scans and so cannot answer an index question. The FK and audit triggers were disabled for the bulk load only, which has no effect on SELECT plans. The single-branch cases are planned as a single predicate here. At runtime `ReadPredicate` sends a single branch to `CompileRead`, so for `every_subject` × `listed_user*` the `ReadBranches` text is not even what runs.
- **How to rerun:** start a `postgres:16.10` container, create database `nava`, load roles (`pg_dumpall --roles-only --no-role-passwords`) and schema from a stack, run `seed.sql`, put `spike_test.go` in a scratch package inside the repo at the PR #765 head, then `SPIKE_PG_URL=postgres://…/nava SPIKE_ALL=1 go test -run TestSpike993 -v`.

**Summary:** the fold is plan-neutral on every seeded ACL. The `caller: self` scalar changes index choice for the better, and it touches no seeded ACL. Accept option A with the corrected wording (findings 2 and 3). Findings 3 and 4 are non-blocking edits to make in PR #765 before merge.
