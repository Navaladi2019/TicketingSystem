The security-flaw check stops going through make, so no other file can quietly change what it checks

In plain words

Goal
Our check for known security flaws (govulncheck, which compares the third-party code we use with a public list of known flaws) must mean what it says when it is green: the code we ship, built with the Go version we ship, has no known flaw it can reach. Nothing outside the check's own file should be able to change that without anyone noticing.
Today
The check runs a command through make, a build tool that reads about twenty small files in our repository. Any of those files can change what the check really does while the line we compare against still looks right. Three review rounds each found and closed one such trick, and then found another. The last one only takes effect inside the CI job (the automated run on GitHub), so a check run anywhere else cannot see it at all.
What's new
The check runs one command directly, with every Go setting that matters written next to it in the workflow file (the file that tells GitHub what to run). That file is already compared character for character with a reference copy we keep, so the command and its settings are now covered by that one comparison. The make commands stay for engineers who run the check on their own machines; they no longer decide anything.
Who is affected
Customers: no change. Engineers: no change in what they see on a pull request (a proposed change). Fewer special checks to maintain.
Risks
Someone who deliberately edits both the workflow file and its reference copy can still make the check pass without checking anything; only review stops that, as before. Three small tool modules (sets of Go code with their own library list) that we never ship are not checked. A change to a checked module's library list can narrow what is checked; such a change always triggers the check and is reviewed.
How we'll know it worked
A trial run on GitHub prints the expected Go version and empty settings. New tests fail first on a bad edit and then pass. The workflow file contains no make.

1. The problem we faced

A required check is a named result GitHub insists on before a change is merged into main. Ours is called vulncheck. Its two scan jobs ran make vulncheck and make vulncheck-temporal-server. We already protect the workflow file with a byte-for-byte reference copy, and we checked that make printed the expected command. But make is a small programming language, and printing the right command is not the same as running it in the right way.

3. The decision

      - name: govulncheck (root module)
        env:
          GOENV: 'off'          # ignore any saved Go settings file
          GOWORK: 'off'         # ignore a go.work that would swap library versions
          GOFLAGS: ''           # no extra build flags
          GOTOOLCHAIN: local    # use exactly the Go that setup-go installed
          GOPROXY: https://proxy.golang.org
          GOSUMDB: sum.golang.org
        run: go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...
  • The right Go. actions/setup-go@v6 installs the exact Go version written in the module's go.mod (go1.27.4), the same one our Docker images use. GOTOOLCHAIN: local stops Go from switching to another. With the older v5 the scan would use go1.27.0 and fail on flaws already fixed.
  • One version number. make check-pins fails unless the workflow, the Makefile and docs/pins.md name the same govulncheck version, with exactly one such line in each scan job.
  • No make in the gate. A new check fails if any step of the workflow runs make. The old checks of make's recipes and settings are deleted.
  • The module layout is bounded. The build fails on a tracked go.work, a tracked vendor/ folder (a hand-editable copy of libraries), or a new go.mod outside the known five. A new go.mod inside the code would quietly take its folder out of the scan.

4. The fix and migration

StepWhat
S4 (first)One trial workflow run at the pinned versions; records the evidence below. Does not hold up this decision.
WorkflowReplace the make steps in govulncheck.yml and its copy; setup-go v5 to v6.
ChecksAdd the no-make check, the version check and the module-layout check, each failing red first. Delete the make recipe and environment checks.
Make, docsLocal make targets run the same command; docs/pins.md records the exception to "every gate runs through make".
LastClose accepted risk AR-TICK-1167-01. PR #950 gets no more review rounds: merged if already approved, otherwise closed.
