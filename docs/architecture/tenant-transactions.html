Tenant-scoped transactions: tenancy.InTenantTx

Every tenant-scoped database access goes through one function. It sets app.tenant_id for one transaction only, and it refuses to run without a tenant. A lint rule keeps everyone else from setting that value.

1. The problem: tenant isolation through PgBouncer

Row-level security (RLS) policies under db/ filter every tenant table on current_setting('app.tenant_id'). That only isolates tenants if the setting is always right for the current work.

The app reaches PostgreSQL through PgBouncer in transaction mode. A server connection belongs to a client only for the length of one transaction. After that it goes back to the pool, and the next transaction on it may come from any client and any tenant.

The failure we must prevent: a setting made at session level outlives the transaction. Tenant A's id would stay on the server connection, and tenant B's next transaction on that connection would see tenant A's rows.

There is a second risk: code paths that set the tenant by hand. Each extra place is one more chance to set the wrong id, or a session-wide one. So there is exactly one place (internal/tenancy), and lint enforces it (PG-N1, R8).

4. Accepted risks

None of these can leak a tenant's setting to another tenant. The first three came from the Security & Multi-Tenancy Reviewer's pass and are rated Low, "will bite us at scale".

The Goexit slot leak Low

If fn calls runtime.Goexit (for example t.FailNow in a test helper), recover() returns nil and err is nil. The transaction is neither committed nor rolled back, and the pooled connection stays checked out for good. A slot leak, not a tenant leak: that connection never goes back to the pool. Proposed fix: keep a committed flag and roll back in the defer whenever it is false.

Rollback on a cancelled context churns connections Low

The rollback uses the caller's ctx. When the error or panic comes from a cancelled request, the rollback fails, and pgx closes the connection instead of reusing it. Safe, because a closed connection carries no tenant (TestFailedRollbackIsJoined proves it), but it costs a reconnect. Proposed fix: tx.Rollback(context.WithoutCancel(ctx)).

boundedToken accepts a bare id Low

The pattern accepts a bare UUID or any single-word value. A library that wrote a bare id as err.Error() into error.type would export it. No library on today's path does this. Already recorded at T01g. If one appears, restrict error.type to the known type and code shapes.

String-concatenation bypass of the lint rule Defence in depth

The analyzer sees constants only. A string built at run time, such as a + b from variables, is not caught. The rule is defence in depth. The database grants are the control (TICK-94 item 15).
