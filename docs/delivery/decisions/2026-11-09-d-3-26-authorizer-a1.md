## 2026-11-09: D-3-26, S10 contract amendment A1: CanWrite takes the transaction and the record rows; only four system sources skip it
- **Decided by:** the Technical Lead on TICK-616 (P3-31), from the Principal Software Engineer's `RESULT: BLOCKED` (option A). Dissent: none.
- **Why:** the S10 contract kept the S9 `CanWrite(ctx, p, entity, before, after map[string]any)`. It has no transaction to read the ACL in, no record row (fixed columns, shares) for `Allows`, and no source, so the evaluator could not be built without passing tenancy inputs through `context`.
- **Decision (A1, binding on P3-31 to P3-37):**
  - `CanWrite(ctx, tx pgx.Tx, p, entity string, before, after *Row) error`, `before` nil on a create; `CanRead(ctx, tx, p, entity, r Row) error` is unchanged. `CanWrite` loads the policy in `tx` and requires `Allows(..., "write", before)` (when non-nil) and `Allows(..., "write", after)`, so a write cannot move a record out of the caller's write scope. Nothing tenancy-relevant travels through `context`.
  - The pipeline builds both rows from `store.Record`; `after` carries the shares of `before`. It skips the authorizer only for the explicit allowlist `rule`, `workflow`, `function`, `system`. `user`, `ai` (no privilege through the AI path) and any empty or unknown source are authorized as their principal.
  - `Row.SharedWith` is pair-matched (AR-S10-01): it holds only shares whose `(principal_kind, principal_id)` names the caller, and `CompileRead` emits the same pair-matched `EXISTS`. A test or fuzzer that builds a `Row` follows the same rule.
  - Masks (P3-33) add the payload maps when they need them, without changing the row check.
- **Cost:** the write check runs after the schema check (the after row is the record as the write leaves it), so a refused writer with an invalid body gets 422 before 403. The read check runs before `If-Match`, so an unreadable record is the missing record's 404, never 428 or 412.
