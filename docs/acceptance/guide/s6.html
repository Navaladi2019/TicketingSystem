API ground rules

Story S6, TICK-48. Contract: api/openapi.yaml; error codes: api/errors.yaml.

What you can test

Every error is application/problem+json (RFC 9457) with a registered code, a type of urn:nava:problem:<code>, fixed detail text and an instance equal to the response's X-Request-Id. Under /api/v1, authentication runs first, so an anonymous caller learns nothing about which routes exist. The contract is published at /api/v1/openapi.yaml and /api/v1/docs. Idempotent replay is tested in S4 (S4.9, S4.10).

Each tenant has its own request budget: a tenant that sends more than its limit gets 429 rate_limited with Retry-After, and other tenants' calls keep succeeding.

Tenant-bound cursors are not externally callable on main (no route lists anything yet): see Home › What is not on main.

Click by click

  1. Run S6.1 and S6.2, or open http://127.0.0.1:18080/api/v1/docs in the browser.Bruno or Browser
    The OpenAPI 3.1 contract, and an HTML page listing GET /api/v1/me and POST /api/v1/operator/tenants. No token needed.
    401 or 404.
  2. Run S6.3–S6.8: unknown routes with and without a token, a path outside /api/v1, a wrong method with and without a token.Bruno
    401 invalid_token (no token under /api/v1, even for an unknown route or wrong method); 404 not_found; 405 method_not_allowed with Allow: GET. Each is problem+json and its instance is urn:nava:request:<X-Request-Id>.
    A text/plain error, an unregistered code, or a 404 to an anonymous caller under /api/v1.
  3. Run S6.9, then find its request id in the logs.Bruno + Git Bash
    docker compose logs nava-core | grep <X-Request-Id from the response headers>
    200 with an X-Request-Id. The log lines for that request carry the same id; the caller's traceparent is linked, not continued.
    No X-Request-Id, or no log line with it.
  4. Run S6.10: a path with markup in it.Bruno
    404 with fixed text: the path is not echoed.
    The body contains <script>.
  5. Run S6.11–S6.13: sign in as Bob, then Alice sends 300 requests at once while Bob sends 20 in the same burst, then Alice waits Retry-After and tries again.Bruno
    S6.12: Alice's first requests are 200 and the rest are 429 rate_limited problems with Retry-After; all 20 of Bob's and S6.12 itself are 200 for tenant B. The console line burst results shows the counts. S6.13: Alice is 200 again.
    No 429 for Alice (no limiter, or a limit above 300 requests in .env), or any 429 for Bob (the limit is shared across tenants).
