Group changes and deprovisioning take effect within 10 minutes

Story S5, TICK-47. Kit: docs/acceptance/s5-group-changes-within-10-minutes.md. Design: ADR-002 (group_paths).

What you can test

nava-groupsync copies each tenant's users and groups from Keycloak every NAVA_GROUPSYNC_INTERVAL (default and maximum 5 minutes). Removing Alice from a group, or disabling her, reaches GET /api/v1/me on her existing, unexpired token after the next cycle: at most 5 minutes of sync plus 5 minutes of token life, so within 10 minutes.

To test in seconds instead of minutes, put NAVA_GROUPSYNC_INTERVAL=15s in .env before docker compose up (Prerequisites does this). The 10-minute bound itself was measured with the default in the S5 kit.

  2. Run S5.5: remove Alice from service-desk. By hand in the console instead: http://localhost:18081/admin › sign in admin / dev-only-admin › realm nava › Groups › t › 00000000-0000-4000-8000-0000000000a1 › service-desk › Members › tick Alice › Leave.Bruno or Keycloak console
    204.
    401: the admin token expired (it lasts 60 s; Send again).
  3. Run S5.6 with the same token. By hand: Send again every 15 s.Bruno
    After one sync cycle (15 s with the .env above, at most 5 min by default) /service-desk is gone and the test reports the time taken, under 600 s.
    Still there after 10 minutes, or the test reports more than 600 s.
  4. Run S5.7 (Bob is unaffected), then S5.8–S5.10 to put Alice back.Bruno
    Bob keeps /service-desk. Alice's /service-desk returns after the next cycle.
    Bob loses a group: a change for tenant A touched tenant B.
  5. Run S5.11 (disable Alice; console: Users › alice › Enabled off › Save) and S5.12 (she tries to sign in).Bruno or Keycloak console
    204, then Keycloak answers 400 invalid_grant, "Account disabled".
    Alice gets a new token.
  6. Run S5.13 with Alice's token from S5.9, still unexpired.Bruno
    After the next sync: 401 tenant_unresolved, while the token's own expiry is still in the future.
    Still 200 after 10 minutes: a deprovisioned user keeps access.
  7. Run S5.14 (Bob still fine), then S5.15–S5.17: re-enable Alice and wait until she resolves again.Bruno
    Bob 200. Alice 200 with /service-desk again.
    Alice stays 401 more than 10 minutes after re-enabling: see Troubleshooting › Alice is stuck.
