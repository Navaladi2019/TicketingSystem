The local stack starts healthy

Story S1, TICK-43. Kit: docs/acceptance/s1-platform-foundation.md.

What you can test

One docker compose up starts PostgreSQL, PgBouncer, Keycloak, Temporal, the Collector, nava-core, the worker, the relay, the purge, nava-onboard and nava-groupsync. nava-core reports its dependencies on /healthz, its readiness on /readyz and its metrics on /metrics.

The admin listener (port 9090) is never published, by design. Postman reaches nava-core's through tools/tunnels.sh up at http://127.0.0.1:19090. For every other service, use docker compose exec, as in step 4.

Click by click

  1. Start the stack from the repository root (see Prerequisites for the first build).Git Bash
    docker compose up --wait
docker compose ps --format '{{.Service}}\t{{.Status}}'
    The command returns, and every long-running service shows Up … (healthy). db-roles, migrate and temporal-schema have exited 0.
    up --wait exits non-zero or a service stays starting/unhealthy. See Troubleshooting › the stack does not start.
  2. Run Postman request S1.1 Liveness: GET /healthz lists every dependency.Postman
    200 and {"status":"ok","checks":{"keycloak":"ok","postgres":"ok","temporal":"ok"}}. All tests green.
    Connection refused: the tunnels are not up (sh docs/acceptance/guide/tools/tunnels.sh up). degraded: one dependency is down.
  3. Run S1.2 Readiness and S1.3 Metrics.Postman
    /readyz is 200 ok. /metrics is Prometheus text with nava_dependency_degraded{dependency="…"} 0 for keycloak, postgres and temporal.
    Any non-200, or a nava_dependency_degraded … 1 line.
  4. Check the other services' readiness from inside their containers.Git Bash
    for s in nava-core nava-worker nava-relay nava-purge nava-onboard nava-groupsync; do
  printf '%s: ' $s; docker compose exec -T $s wget -qO- http://127.0.0.1:9090/readyz; echo
done
    Six lines, each ending ok.
    server returned error: HTTP/1.1 503 or exec failed.
  5. Stop Keycloak, then repeat S1.1 and S1.2 after about 10 seconds. Start it again.Git Bash + Postman
    docker compose stop keycloak
# Postman: S1.1 and S1.2 again
docker compose start keycloak
    S1.1 now returns "status":"degraded" with "keycloak":"fail" (its test turns red: that is the point). S1.2 stays 200: a Keycloak outage does not stop traffic.
    /readyz turns non-200 while only Keycloak is down.
  6. Stop PostgreSQL, repeat S1.2, then start it again.Git Bash + Postman
    docker compose stop postgres
# Postman: S1.2 again (within 5 s)
docker compose start postgres
    S1.2 returns 503 within about 2 seconds: nava-core stops taking traffic.
    /readyz stays 200 more than 5 seconds after PostgreSQL stopped.
  7. Run S1.4 and S1.5: the admin routes on the public port.Postman
    404 problem not_found for /healthz and /metrics on http://127.0.0.1:18080.
    200: an admin route is reachable on the tenant ingress.
  8. Run S1.6: Keycloak's discovery document for realm nava.Postman
    200 with issuer = http://localhost:18081/realms/nava, the one issuer nava-core trusts.
    A different issuer: tokens will be refused everywhere (see Troubleshooting › 401 everywhere).
