A tenant user signs in and is scoped to their tenant

Story S3, TICK-45. Kit: docs/acceptance/s3-tenant-signin.md.

What you can test

A seeded user signs in through Keycloak (realm nava, client nava-web) and calls GET /api/v1/me. The tenant comes only from the token's organization and the platform's own binding table. A missing, garbage, tampered, expired, foreign or ID token is 401 invalid_token; a token that names no organization or two is 401 tenant_unresolved.

There is no web UI yet. Bruno's token request does the sign-in that the Keycloak login page will do for the web app. To see the login page itself, open http://localhost:18081/realms/nava/account and sign in as alice@tenant-a.test.

Click by click

  1. Run S3.1 Sign in as Alice.Bruno
    200 from Keycloak. Tests check iss = http://localhost:18081/realms/nava, aud has nava-api, typ Bearer and organization.tenant-a.id = 00000000-0000-4000-8000-0000000000a1.
    401 invalid_grant (wrong password, or Alice is disabled: see S5 restore steps). A different iss: you called Keycloak by another host name; use {{keycloak_url}} as shipped.
  2. Run S3.2 Alice: GET /me.Bruno
    200 with tenant_id tenant A, a platform user_id (not her Keycloak id), non-empty groups, idp_alias "" and group_paths such as /service-desk and /ou/eng/platform.
    401 tenant_unresolved: the seed or the first group sync has not run (tools/seed.sh).
  3. Run S3.3 and S3.4 (tenant A's admin).Bruno
    200, tenant A.
    Any other tenant, or 401.
  4. Run S3.5 (no token), S3.6 (garbage) and S3.7 (payload changed to tenant B).Bruno
    Each is 401 application/problem+json with code invalid_token; S3.5 also sends WWW-Authenticate: Bearer. S3.7 names nothing of tenant B.
    A 200, or a 500.
  5. Run S3.8 (Alice's ID token as a bearer), S3.9–S3.10 (a master-realm token) and S3.11–S3.12 (an operator token).Bruno
    All three are 401 invalid_token.
    Any 200: a token the API must not trust was accepted. Report it at once.
  6. Run S3.13–S3.15: create Dave (in no organization) through the Keycloak admin API, sign in, call /me.Bruno
    Dave signs in (Keycloak knows him) but /me is 401 tenant_unresolved.
    200 for Dave.
  7. Run S3.16–S3.21: create Carol, add her to both organizations, sign in asking for organization:*, call /me.Bruno
    Her token names two organizations; /me is 401 tenant_unresolved and names neither tenant.
    200 with either tenant: the platform guessed a tenant.
  8. Last folder, S3.22: the token from S3.1 once it is more than 5 min 30 s old (5 min lifespan plus the 30 s clock skew nava-core allows).Bruno
    401 invalid_token. In the Runner the request waits until the token has expired.
    200 more than 30 s after the token's exp: an expired token was accepted. (Within 30 s of exp, 200 is expected: that is the skew allowance.)
  9. Optional: see the Keycloak login page.Browser
    Open http://localhost:18081/realms/nava/account, click Sign in, enter alice@tenant-a.test / dev-only-alice. The account page shows Alice.
    "Invalid username or password": the realm was not imported (fresh down -v, then up).
