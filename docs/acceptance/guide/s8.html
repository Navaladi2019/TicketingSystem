A tenant admin publishes an incident type and reads every version

Story S8, TICK-333. Kit: docs/acceptance/s8-entity-types.md (TICK-346).

What you can test

Every tenant starts with three ticket types: incident, request and change, at version 1. A tenant admin publishes a changed incident as version 2. Every version stays readable exactly as it was published. A change that would break existing tickets, such as a field changing type, is refused and nothing is stored. A user who is not an admin can read the types but cannot publish them, and another tenant sees only its own types.

The story's users are seeded under these names: admin@tenant-a is admin@tenant-a.test (tenant A's admins group, which tools/seed.sh creates), agent@tenant-a is Alice (alice@tenant-a.test) and agent@tenant-b is Bob (bob@tenant-b.test). Run tools/seed.sh again after you pull this change: earlier runs did not create the admins group or the types.

Not in this story

Creating tickets of these types, editing a published version (never allowed), and a UI for publishing. The concurrency of publishing (50 publishers at once get versions 2 to 51) and the database-level guarantees are in the CI tests (TestPublish* in internal/server, the CI-9 report), not in this guide.
