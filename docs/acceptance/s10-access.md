# Acceptance kit: S10, record access by group, requester and field masks

Story TICK-336, kit TICK-623 (P3-38). Story branch `TICK-336/group-acl-masking`.
Bruno folder: `docs/acceptance/guide/bruno/S10/` ("S10 access"), generated by `docs/acceptance/guide/build/collection.py`.
Stack case: `deploy/compose/test/cases/s10_access.sh`. Evidence: `docs/acceptance/s10-evidence/`.

## What you can now do

- Agents see only the incidents assigned to their own groups. Requesters see only the incidents they raised. A list's `total` counts the same set.
- An incident you may not see looks exactly like one that doesn't exist (the same 404).
- A tenant admin can hide a field from everyone outside a group. A hidden field can't be filtered, sorted or written by anyone the mask leaves out.
- A tenant admin can ask why a user can read a given incident, and gets the rule that grants it.

## Known limits

- **A deny names no rule.** Rules are allow-only, so a `deny` has `rule_id: null` (`api/paths/access.yaml`). The kit asserts that. The story's "names the denying rule" is met as "names no granting rule". If a named deny reason is wanted, it is a new feature.
- **A data property can't be sorted at all.** `sort=description` is `400 validation_failed` for every caller, admin included. So the kit shows the masked-sort case on `assignee`, a sortable fixed column. Neither answer reveals anything.
- **`requester@tenant-a` is the seeded `auditor@tenant-a.test`.** The realm has no dedicated requester user, and adding one changes the directory test's user set. The auditor's `audit.read` plays no part in record reads.
- **Exact `total` needs one page.** The C1 and C2 `total` checks need all items on one page (`next_cursor` null at `limit=200`). That holds on a fresh stack and for many re-runs.
- **The Temporal image was pulled, not built.** It is main's prebuilt image, built with Go toolchain 1.26.10, so TICK-699 is not in it. Everything else was built from the branch. See `s10-evidence/fresh-stack-setup.md`.
