    S10: A service-desk agent sees only their group's incidents; masked fields stay hidden

    Story TICK-336 (kit TICK-623). Verdict READY, 2026-11-11, recorded in the acceptance kit. C1 to C5, A3 and the admin routes pass.

    What a user can now do

    • As an agent, see only the incidents assigned to your own groups. As a requester, see only the incidents you raised. A list's total counts the same set.
    • Open an incident you may not see and get exactly the 404 a missing id gets.
    • As a tenant admin, hide a field from everyone outside a group. A hidden field cannot be filtered or sorted (400 masked_field) or written (422 field_not_writable) by anyone the mask leaves out.
    • As a tenant admin, ask why a user can read an incident and get the granting rule (explainAccess). Publishing an access policy is audited under acl_policy.

    How to try it

    1. On a fresh stack, sh docs/acceptance/guide/tools/seed.sh, then sh docs/acceptance/guide/tools/tunnels.sh up.
    2. In Bruno run the folder S10 (66 requests), or headless sh docs/acceptance/guide/tools/api-test.sh S10. At S10-31 the admin publishes masks on description and assignee; S10-66 removes them.
