            S14: Every record and entity-type change lands in one audit log

            Story TICK-419 (kit TICK-437). Verdict READY, 2026-11-04, recorded in the acceptance kit. All four criteria and the isolation check pass.

            What a user can now do

            • As a tenant admin or auditor, see every entity-type publish and every incident change of the tenant on one timeline, newest first, with who, from where, and what changed.
            • See entity-type versions that existed before this release on that timeline, marked backfilled.
            • As an agent, read an incident's own history but not the tenant's timeline (403). Another tenant sees nothing of yours.
            • Be refused when a publish would store a secret value in an entity-type schema: 422 config_secret_in_content, naming the path and never the value.

            createRecord POST /api/v1/records/{entity} Create a record of an entity type 201, 400, 401, 403, 404, 409, 422, 429, 500, 501, 503
            patchRecord PATCH /api/v1/records/{entity}/{id} Update a record with a JSON Merge Patch 200, 400, 401, 403, 404, 409, 412, 422, 428, 429, 500, 501, 503
            getRecordHistory GET /api/v1/records/{entity}/{id}/history A record's change history 200, 400, 401, 404, 422, 429, 500, 501
            getMe GET /api/v1/me The calling user and tenant 200, 401, 429, 500, 501

            How to try it

            1. sh docs/acceptance/S14/tools/upgrade-setup.sh: it starts a stack at main, publishes a version, upgrades to this checkout and seeds (needed because AC2 is about versions that existed before the release).
            2. sh docs/acceptance/guide/tools/api-test.sh S14A, or open the folder S14A ("S14 audit") in Bruno. Folder S14 ("S14 audit timeline") holds the read-only reader checks.

            Verdict and evidence

            • Verdict: READY, 2026-11-04, four of four criteria pass.
            • Recorded run used: the kit's committed run-summary.json for folder S14A (21 requests, 76 of 76 tests), on a fresh stack. The S14 reader folder's 10 requests and 28 of 28 tests are stated in the kit README, not in that file. Not re-run for this page.
            • Known limit: tenants that existed before S14 have no auditors group until nava-onboard reconcile-auditors runs; until then only tenant admins hold audit.read.
