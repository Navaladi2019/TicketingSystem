    8. Audit export and erasure

    Boundary

    Tenant B, holding a valid token or a database login bound to tenant B, must not export, erase, hide or learn the existence of tenant A's audit entries. Only the nava_erasure role can erase, it cannot read what it erases, and every erasure must be visible to the offline verifier.

    Enforcement point

    Lowest layer first (ADR-004 R11, R17, R19 to R24, ADR-004-A1):

    • audit_log RLS on every read and every erase transition.
    • Column grants. Only nava_erasure may update the erase columns; nava_app and nava_worker get 42501. nava_erasure's SELECT grant leaves out diff and diff_salt, and only nava_audit_reader may read them.
    • R11 BEFORE UPDATE trigger. An entry can be erased once; a second erase is rejected.
    • Export, lease and reseed predicates. The export page read, the export lease and the reseed gate each filter on the caller's tenant, under RLS. The lease is a per-tenant row, so one tenant's export never blocks another's.
    • Write-time and read-time secret checks. Secret values are refused at write (R6) and masked at read (R7), so they never reach export bytes.
    • The erase helper is test-only. No cmd/* binary links internal/audit/erasetest.
    • Offline verifier, step 7. A diff nulled without a sealed erase entry verifies tampered; an unsealed erase verifies pending (see audit chain).

    Proving tests

    Guard Test
    audit_log RLS TestCIA4EraseNeverCrossesTenants, TestCIA4NoTenantContextReachesNothing
    Erase-column grants TestCIA7AppAndWorkerCannotErase
    R11 trigger TestCIA7SecondEraseIsRejected
    No diff read for nava_erasure TestCIA7ErasureCannotReadDiff, TestP510bErasureCannotReadDiff
    Verifier step 7 TestCIA7NulledDiffWithoutEraseEntryIsTampered, TestCIA7EraseVerifiesPendingThenPass
    Export page and stubs TestCIA4ExportAndStubsNeverCrossTenants
    Export lease TestCIA4ExportLeaseIsPerTenant
    Reseed gate TestCIA4ReseedReadsOnlyItsOwnHead, TestReseedGateIsTenantScoped
    No secret in export bytes TestCIA5ExportBytesCarryNoCanary
    Erase helper not shipped TestNoBinaryLinksTheEraseHelper

    The CI-A4 and CI-A5 tests run through the real handler, sealer and offline verifier in make test-integration.

    Fixture that turns it red

    Each guard was shown red with only that guard removed; the table with each mutation and its result is in audit-erasure-export-isolation.md. For example, with audit_log RLS disabled tenant B erases tenant A's entry, and with the R11 trigger disabled a second erase moves erasure_ref. Each test pins its own layer: the masker failing closed, or the read-time mask, is not counted as the guard.

    AR-TICK-409-06 🟠 Medium Whoever holds the nava_erasure credential can null audit diffs and record a valid erase entry: visible as erasure, but still loss of evidence. Accepted (ADR-001-A6, 2026-11-02) Security reviewer Any new holder of the credential, or erasure moving off the job runner ADR-001-A6 A6.1
    AR-TICK-549-01 (A1 in-process misuse) 🟡 Low The nava_audit_reader DSN lives on the nava-core host. Code inside nava-core that deliberately opens a second pool with it reads raw audit_log.diff and diff_salt, unmasked. Guard rule 1 (only cmd/nava's config loader reads the DSN; only internal/audit/read calls read.OpenPool) and review cover it; cross-tenant reads stay closed by FORCE RLS. Accepted by Security (RFC-012 round 1); Accepted (ADR-004-A1, 2026-11-04) Security reviewer A second service needs audit reads, or tenant code (I8) runs in-process ADR-004-A1 Accepted risks
