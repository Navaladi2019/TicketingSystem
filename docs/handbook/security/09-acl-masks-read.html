    Handbook / security / 9. ACL and field masks on the read side

    9. ACL and field masks on the read side

    Boundary

    A user of the right tenant whom the record ACL does not admit, or who may not read a masked field, learns nothing about that record or field through any read surface: get, list (filter, sort, total, cursor), history, the access explainer, or an error response. A record they cannot see answers exactly like a record that does not exist.

    Enforcement point

    internal/authz is the one authorization layer (ADR-001 I5), evaluated inside the query and in the caller's tenant transaction:

    • Rows. CompileRead turns the tenant's published policy into the WHERE of the record query, with the share EXISTS matched on tenant_id and the (kind, id) pair. canRead maps a hidden record to the missing-record 404, before If-Match, so there is no 403 or 412 oracle.
    • Fields. authz.Shape drops masked fields from every response body, including history before and after (changed is computed after shaping). History also drops org_unit_id for every reader, because no mask can name it. The audit list and the audit export redact masked fields, and org_unit_id with a masked requester (TICK-1119, TICK-1127).
    • Queries. checkPlan (authz.CheckQueryFields) refuses a filter or sort on a masked field with a 400 before any SQL runs, so neither the result, the total nor the timing depends on the hidden value.
    • Explainer. Requires the tenant admin first, runs in the caller's tenant, and lists only masked fields the admin can read.
    • Subjects. authz.NotInTenant refuses another tenant's group or user in a policy or mask, with the same 422 as an unknown id (foreign_id in a format-2 document; the id is not echoed). Since S30 the database repeats it: the acl_versions_tenant_ids trigger (SECURITY INVOKER) refuses a row naming another tenant's id, and no runtime role can turn it off.
    • Composed rules (S30). A ref resolves only inside the same document and version, never across tenants. A policy the planner cannot use is voided: it grants nothing on any read surface and the explainer lists it under invalid. Only nava_app may insert an acl_versions row (ADR-010-A1 A1-3).

    How the ACL is compiled and how masks apply are on Core: ACL and Core: field masks.

    Region access (S31)

    The full review is s31-org-unit-isolation.md (TICK-952): no exploitable isolation gap. Every guard holds at the database: FORCE RLS on org_units, org_unit_members and org_unit_closure, grants, and foreign keys that carry tenant_id. The under leaf and the primary-unit lookup also filter by tenant on top of RLS.

    An orphaned unit (its parent missing, which only a forged row can produce) has no closure row, so under is false and not under is true for it. The count of such units is the metric groupsync_org_closure_unrooted_units, and GroupsyncOrgUnitsUnrooted fires when it grows.

    Within one tenant. The list shape the probe picks can show in latency whether more than K* records sit under a policy's units: one coarse bit, counting records the caller cannot read, inherent to ADR-010-A2 and accepted as AR-TICK-1040-01. A slow probe's SQL text includes LIMIT K*+1, so keep log_min_duration_statement and auto_explain off for the app role and never ship the PostgreSQL server log anywhere a tenant can read it. A cancelled or failed probe is logged whatever these settings are, so the log rule is the one that must hold. A user moved out of a unit keeps under access until the next sync (AR-TICK-901-01, ADR-010 R3). A wrong closure row outside the touched subtrees, which only a group-sync bug or a database credential can write, lasts until an applied run with no tree change (AR-TICK-1118-01). After an operator repairs a stored org_unit_id property, no mask can be added for the old name (AR-S31-04).

    Fixture that turns it red

    Each S10 row was shown red by a named mutation: checkPlan returning nil gives 200 on a masked filter; canRead answering 403 fails the oracle check; no shaping puts cost into history after; the explainer's Readable filter dropped names a field the admin cannot read. Row 7 (share forgery) needs both the tenant predicate dropped and RLS off on record_shares to go red, which shows the two layers are independent.

    Accepted risks

    Errors and logs are part of the read side: AR-006 (a recovered panic value is logged as is) and AR-010 (error.type export shape) apply here.

    S30 added AR-S30-01 (under refused at the route only), closed by TICK-947, and AR-TICK-971-01 (a crafted document costs up to about 90 ms per publish at the default byte limit, about 340 ms at the 128 KiB ceiling), on the ADR-010-A1 page and in accepted-risks.md.

    AR-TICK-1040-01 (region-list latency shows whether more than K* records sit under a policy's units) 🟡 Low ADR-010-A2 A2-6. The capped probe picks the under list shape (C3 at ≤ K* records, the walk above), so a list's response time can reveal whether more than K* records of that entity type sit under the leaf's units U. Rows returned never change, the count never leaves the server, and the bit stays inside the caller's tenant. K* = √(page × N̂_e) also lets timing hint at the tenant's rough record volume of that entity type. Under ADR-010-A3, time-to-response can also reveal two more bits about the same entity type, both inside the caller's tenant: whether N̂_e exceeds α·U_cert (about 33,400 records, where the closure count is skipped), and whether S has at least ⌈N̂_e/α⌉ units (R is chosen).     AR-TICK-1118-01 (a wrong region-tree row outside the changed units lasts until a run with no tree change) 🟠 Medium ADR-010-E4 E4-7. A wrong row elsewhere lasts until such a run, with no time limit. An extra row grants through under and hides through not under; a missing row does the reverse. Either can let a user read or change tickets outside their rules, or refuse them tickets inside their rules, inside one tenant (FORCE RLS, FKs that carry tenant_id). Only a group-sync bug, the migrator, a superuser or a holder of group sync's database credentials can cause it; no user token can. No metric counts drift repairs (TICK-1124).
