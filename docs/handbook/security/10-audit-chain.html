    10. Audit chain and offline verify

    Boundary

    Each tenant's audit entries are sealed into its own hash chain. Anyone holding an export can check it offline, with no access to the platform, and any edit, deletion, reordering, relabelling to another tenant, or unrecorded erasure is reported as tampered.

    Enforcement point

    • Append. internal/audit takes the tenant from the transaction (TenantOf), never from a parameter; with no tenant it writes nothing.
    • Seal. The sealer assigns each tenant's entries a gapless seq and links each entry hash to the previous one, per tenant, under that tenant's head lock. The tenant id is part of the hashed envelope, so moving an entry to another tenant breaks the chain.
    • Verify. nava audit verify <file> (cmd/nava, package internal/audit/verify) streams the export once and recomputes every hash. It links no network, database or platform package other than the chain and verify packages, so it runs on an auditor's machine.
    Outcome Exit When
    pass 0 every check holds
    tampered 1 the first failing check, with its reason code
    (usage) 2 bad arguments, unreadable file
    pending 3 an erased entry is listed only by an unsealed erase entry
    unverifiable 4 a stubs=false file, honestly flagged
    empty 5 no sealed entry in the window

    The table is from the normative audit-verify.md.

    Proving tests

    Attack Test
    Relabel an entry to another tenant TestAdversarialTenantRelabelBreaksChain, TestUnsealedTenantMismatch
    Sealers of two tenants, or two sealers of one tenant TestSealTenantIsolation, TestConcurrentSealersNeverDuplicateSeq
    Change any field TestEveryFieldIsHashed, TestChainBreaks
    Byte edits, deleted or duplicated lines, re-anchoring TestGoldenVectorsTampered, TestTamperedExportsFail, TestSeqDuplicateAndMissing, TestAfterSeqAnchorsOnThatSeq
    Honest exports still verify TestFilteredExportsVerify, TestUnfilteredExportVerifies, TestStubsOmitted
    Exit codes are stable and documented TestExitCodes, TestHelpDocumentsExitCodes
    The verifier stays offline TestImportBoundary, TestOfflineImports
    Append takes the tenant only from the transaction TestAppendTenantFromTransaction, TestAppendNoTenant

    Fixture that turns it red

    The golden tampered vectors (internal/audit/chain/vectors) are committed export files that must each fail with a fixed reason code; an honest vector set must pass. The S13 acceptance run shows the same by hand with the built binary: an untouched export exits 0, a byte-edited one and a line-deleted one exit 1 (see S13 acceptance).

    Accepted risks

    AR-TICK-409-01 is the main one: the chain has no external anchor in M1, so the database owner or migrator could rewrite a whole tenant's chain consistently.

    ID Sev Risk Status Owner Revisit trigger / proposed fix Source
    AR-TICK-409-01 (R-A1) 🟠 Medium The audit hash chain has no external anchor in M1. The database owner or migrator can rewrite a tenant's whole chain consistently, and only a checkpoint trailer from an export the tenant already holds detects it. Accepted (ADR-004, 2026-11-02; external anchoring deferred by the CTO) Solution Architect, tracked by the CTO A regulated buyer asks for external attestation: periodic checkpoints to object-locked storage or RFC 3161 timestamps ADR-004 Accepted risks
    AR-TICK-409-02 (R-A2) 🟡 Low Audit entries stay unchained until the sealer runs: about 10 s for active tenants, up to 300 s after idle, longer if the seal lineage dies. Accepted (ADR-004, 2026-11-02) Technical Lead audit_unsealed_oldest_seconds alert (600 s) fires in production ADR-004 R16, R17
    AR-TICK-422-01 (RS-E1-1) ⚪ Info cascade_cycle audit entries use a cascade_key subject, so they are not in the per-record history, and no index finds them by record id without the origin and definition. Accepted (ADR-004-E1, 2026-11-02) Solution Architect A caller needs cycle rows by record; add the measured partial index on the diff's record_id ADR-004-E1 Accepted residuals
