    Core: record write pipeline (write, read, list)

    Purpose

    pipeline.Write is the only way to create or update a record (ADR-001 I4). It runs inside the caller's tenancy.InTenantTx transaction and never commits, so the record, its write key, its audit entry and whatever the EventSink wrote commit together or not at all. Reads go through pipeline.Get and pipeline.List; only the pipeline imports internal/records/store. The rules are in the normative record-write-pipeline.md.

    Entry point

    • HTTP: createRecord (handlers.CreateRecord, internal/server/records.go), patchRecord (internal/server/records_patch.go), getRecord, listRecords (internal/server/records_list.go).
    • Go: (*pipeline.Pipeline).Write(ctx, tx, pipeline.Command) in internal/records/pipeline/pipeline.go; pipeline.Get, pipeline.QueueGet and pipeline.List in internal/records/pipeline/read.go.
    • Other writers (workflows, rules) call the same Write with a system Source; the architecture test TestRecordWritersOnlyInPipeline fails on any other writer of records.

    Read and list

    • Get: pipeline.Get answers a record created in the same transaction from the memo, otherwise store.Get. The handler then calls ACL.CanRead (unreadable is the same 404 as missing) and shapes the body with authz.Shape. pipeline.QueueGet puts the read in the GET's single batch.
    • List: the handler builds the predicate with authz.CompileRead (or authz.ReadBranches for one index-ordered branch per subject) and checks every filter and sort field with authz.CheckQueryFields, before any SQL. store.List (list.go) counts (capped at TotalCap) and pages by keyset over a listable column; a data-property filter runs under DataFilterTimeout and maps a cancel to ErrStatementTimeout.
    • Proving tests: TestCompileReadAgreesWithAllows, TestBranchedStatements, TestTimedOutMapsOnlyADataFilterCancel.

    Errors

    Written by hand from the mapping in handlers.recordError (internal/server/records.go) and the PATCH handler (internal/server/records_patch.go), statuses from api/errors.yaml. Every pipeline error raised after the definition was read is wrapped in *pipeline.ErrAtVersion, so error pointers are built from the version the write used.

    Pipeline result HTTP code
    ErrNotFound (also an unreadable record on update) 404 not_found
    authz.ErrForbidden 403 forbidden
    *authz.ErrFieldNotWritable 422 field_not_writable
    *ErrValidation (incl. rule audit_secret_in_diff) 422 record_invalid
    *ErrIllegalTransition 422 illegal_transition
    ErrAssignmentGroupRemoved 422 assignment_group_removed
    *ErrUniqueViolation 409 unique_violation (names the property only)
    ErrVersionConflict 412 version_conflict (current ETag re-read)
    ErrRetryable (deadlock, serialization failure, allocation timeout) 503 retry_later
    foreign-key 23503 on a fixed column 422 record_invalid (rule reference)
    ErrInvalidCommand, *ErrIdempotencyConflict, outbox.ErrCascadeTooDeep 500 internal_error: the HTTP handlers never send a key or causation, so these are system-writer results only

    The HTTP request's own Idempotency-Key is a separate layer (idempotency_keys, 409 idempotency_key_reuse / idempotency_in_flight), not record_write_keys.
