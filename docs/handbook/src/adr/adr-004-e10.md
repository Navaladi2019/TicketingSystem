## Problem

TICK-1121 lets an admin publish a clean ticket type over a stored version that holds a NUL character, their only repair path. The audit diff is built from the old version, and PostgreSQL `jsonb` refuses NUL, so each NUL is written as the text `\u0000` first. A reader must be able to tell that this happened, and nobody may hide or fake it.

## Decision

- New column `audit_log.diff_nul_escaped boolean NOT NULL DEFAULT false`, set when at least one NUL in the previous schema was escaped.
- It is an envelope member **emitted only when true**. Rows written before E10 are all false, so their canonical bytes and hashes are unchanged and they still verify: no cut-over, no envelope version, no re-hash. In an export line, the member absent means false, `true` is the only allowed value, and `false` or `null` is `malformed_line`. Flipping the column or stripping the member gives `envelope_sha256_mismatch`.
- Exposed everywhere `diff_truncated` is: the reader role (A1-1 now 31 columns), the read endpoints, JSONL (only when true; format stays v1), CSV (new column after `diff_truncated`, `true` or empty; the old header still verifies).
- A key collision (two keys of one object whose escaped forms are equal, including two NUL keys) is not refused: the diff becomes one root `replace` op, which carries no old content, and the publish answers 201.
- `audit_log_guard_update` is recreated with the column, so no role can change it. In CSV an empty cell means the member is omitted.
- Ordering is enforced: until the envelope member, sealer and verifier are on `main`, a `BEFORE INSERT` trigger refuses a row with the flag true (`23514`).
