## Problem

A1 says `make vulncheck-temporal-server` is a required `ci.yml` step. Since 10 November it runs in `govulncheck.yml`: every second day, by hand, and on pull requests that change `go.mod` or `go.sum` of either module. The `root` scan is not a required check of `main`. The `temporal-server` scan shares its name with the required `ci.yml` job that tests the Authorizer. E4 assumed GitHub counts the green one. The shared name was removed by PR #900 (2026-11-25), and TICK-1146 showed a later run does replace a red check (PR #902), so neither scan reliably blocks until FU2.

## Decision

| # | One line |
|---|---|
| E4-1 | Decision 3 is reworded to what is built. Zero findings, no exception: unchanged. |
| E4-2 | A library update that clears a finding is an ordinary bug fix after a green `ci:full` run, unless it moves a Temporal pin, changes an Authorizer golden file or uses `replace`, `exclude` or a fork (triad), or moves a trust-path library (Security review). The scanned Go must equal the shipped Go. |
| E4-3 | Until FU2, the agents' rule stops a merge: each job `success`, `skipped` or missing is red. Until TICK-1146's fix is merged, the reviewer reads every check run on the head commit, not the merge box. |
| E4-4 | A new job `vulncheck` always reports and becomes required. It carries that name only on pull requests into `main`. Contract: `docs/adr/ADR-001/E4/vulncheck-contract.md`. |
| E4-5 | No two workflows report the same check name (done by TICK-1145, PR #900). |
| E4-6 | The two-day schedule stays (the owner's decision). |

## Options that lost

Not required, as today; required with the `paths` filter kept; a scan on every pull request; a conditional job in `ci.yml`; scanning both modules on any library change; a list of required names; a copy of the `jobs:` block only; no pull request scan; no erratum.

## Accepted risks

AR-TICK-1140-01: a new flaw can stay unseen on `main` up to about 50 hours. AR-TICK-1140-02: until FU2, a red scan can be merged (the name collision was fixed by PR #900). AR-TICK-1140-03: a pull request can edit the gate that judges it.
