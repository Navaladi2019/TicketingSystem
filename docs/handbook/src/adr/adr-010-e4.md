## Problem

A2-2 said every org-tree change deletes and re-inserts the tenant's whole `org_unit_closure`, under an advisory lock of its own, with a config audit entry. What was built replaces only the affected rows, under the lock group sync already holds, with no audit entry.

## Decision

| # | One line |
|---|---|
| E4-1 | A run that touched units deletes and re-inserts only the affected units' closure rows, in the tree write's transaction. |
| E4-2 | The full rebuild stays for an empty closure, for drift found by a set comparison, and for `org_unit_closure_rebuild_all()`, which blocks every tenant's reads of three tables until it commits: maintenance window only (TICK-1122). |
| E4-3 | One lock: group sync's per-tenant try lock. A second sync skips the tenant. A2-2's own lock must not be added. |
| E4-4 | After a delta, the affected units' rows equal the full rebuild's. |
| E4-5 | No config audit entry: the closure is derived from a Keycloak mirror. |
| E4-6 | Whole sync at 10,111 units, two CI runs: leaf move 70 / 144 ms, country 95 / 216 ms, region 224 / 468 ms, full rebuild 0.83 / 1.77 s. A large import into a closure that is not empty is slower (TICK-1123). |
| E4-7 | A run that touched units, and an unchanged-snapshot cycle, do not check for drift. |
| E4-8 | `nava_groupsync` also holds `SELECT` on the closure. |

## Residuals

`AR-TICK-1118-01` in [accepted risks](../security/accepted-risks.md): a wrong row outside the touched subtrees lasts until the next applied run with no tree change. Through `under` or `not under` it can show or hide tickets, inside one tenant only.
