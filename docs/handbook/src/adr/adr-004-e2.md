*Paraphrases: "Decision", "Outcome table".*

## Problem

R20 said an export made with `stubs=false` always reports `verifiable: false`. That judged some honest files `tampered`, for example a filtered window whose last entries were excluded.

## Decision

- The header's `stubs` field is the request, not a claim. It only decides whether every `seq` in the range must appear (a `stubs: true` file with a gap is `tampered`).
- Only the trailer's `verifiable` must equal the computed value; a disagreement is `tampered` (`verifiable_flag_mismatch`).
- "Computed" includes the tail: the range is contiguous only if the anchor is present, no `seq` is skipped, and the last range line is `last_seq`. An honest `stubs: false` export that excluded the tail is `unverifiable`, not `tampered`.
- The exporter still streams: it counts as it goes and writes `verifiable = (range non-empty) and (count + stub_count = last_seq - anchor_seq)`.
- The verifier's reason codes become a closed list.
- Not a breaking change to v1: every file that passed still passes, and no exporter had shipped. The format stays `nava.audit.export/v1`.

A binding outcome table in the record maps header `stubs`, range shape and trailer flag to `pass`, `unverifiable` or `tampered`.
