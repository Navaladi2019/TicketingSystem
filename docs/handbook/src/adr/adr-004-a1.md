## Problem

ADR-004 masks secret pointers in `audit_log.diff` when it is read, and only `internal/audit/read` runs the masker. But `nava_app` also held column SELECT on `diff` and `diff_salt`, so any `nava_app` query elsewhere returned the raw diff. Row-level security limits rows, not columns, and the static guard reads Go source, so it cannot see SQL built at runtime. Nothing read the diff outside the reader, so this closed a latent risk, not a live exploit.

## Decision

A dedicated login role, `nava_audit_reader`, is the only runtime role that can read `audit_log.diff` and `diff_salt`. It has its own PgBouncer login and its own connection pool, held by `internal/audit/read`. `nava_app` loses both column grants.

- The role has SELECT only, on listed `audit_log` columns and on `entity_definition_versions (definition_id, schema)`; no memberships, no other grants.
- `audit_log_select` is limited to `nava_worker`, `nava_erasure` and `nava_audit_reader`; `nava_app` gets row access only through the generated writer policy.
- The masker fails closed: if a definition has no visible version row, the request fails with a 500 and returns no diff.
- The pool is capped at 5 connections, in PgBouncer and in the Go pool. The reader's DSN is read only by the config loader.
- Record history is two transactions: `nava_app` checks the record first (same 404 for missing, unreadable and other-tenant), then the reader pool reads entries.
- CI-A3 gains a catalogue check that no other runtime role holds SELECT on `diff` or `diff_salt`, on the table or any partition, and that the policy's role list is exact. The earlier static guard stays as a second layer.
- The role, the revoke and the reader pool land in one PR, because between them the audit endpoints would return 500.

## Options that lost

A narrow `SECURITY DEFINER` function (breaks the no-definer-function rule); `SET ROLE` (needs a role membership, also forbidden); masking in a database view or function; keeping only the static guard; granting the reader `records`; a `CONNECTION LIMIT` instead of a pool cap.

## Accepted risks

| Id | Risk |
|---|---|
| AR-TICK-549-01 (Low) | Code inside the core process that deliberately opens a second pool with the reader DSN reads raw diffs. The guard and review cover it. |
| AR-TICK-549-02 (Info) | One more pool: up to 5 server connections per PgBouncer instance. |
