*Summary. The normative text is the linked `.md`.*

## Problem

ADR-007 D1 let a host app ask Keycloak for the bare `organization` scope and rely on Keycloak's organization picker. Spike S1 showed that on a user's first sign-in through their company's identity provider, Keycloak brokers before the picker runs. The token then has no `organization` claim, and the unchanged tenant resolver answers 401 `tenant_unresolved`. No token resolved to the wrong tenant: it is a sign-in gap, not an isolation gap.

## Decision

| # | One line |
|---|---|
| D1-A1.1 | Every authorization request from an embedding client carries `organization:<alias>` for the tenant the host acts for. The alias is a hint, never a trust input: the tenant still comes only from the signed `organization.id` (ADR-001 I2). |
| D1-A1.2 | The host should also send `kc_idp_hint` of the same tenant, so a user with a live company sign-in gets no prompt. |
| D1-A1.3 | `GET` and `PUT /api/v1/embedding-clients/{client_id}` return the pair `organization_alias` (`t-<uuid>`) and `idp_hint` (`idp-<uuid>`), derived from the caller's resolved tenant id alone. No table is read to produce them. |
| D1-A1.4 to A1.6 | An alias the user cannot use gives a sign-in form, an `invalid_scope` error, or a token with no `organization` claim that gets 401. No path yields a token for a tenant the user is not in. |
| D1-A1.7 | D13 gains an audited, tenant-admin-only `GET`. The role check runs before any lookup, and another tenant's `client_id` gets the same 404 as an unknown one. `PUT` refuses the two read-only members with 400 `unknown_field`. |

`Resolve`, the Keycloak realm file and `nava-web` do not change.

## Tests it adds

CI-E2 is restated, and CI-E14a to d, CI-E15 and CI-E16 (an isolation test under `internal/tenancy/isolation/`) are added. Every E14 case asserts that no issued token names an organization the user is not in. They land with the ADR-007 stories S23 (TICK-802) and S26 (TICK-803), planned in PLAN-008.

## Residuals

RR-A1-1 to RR-A1-6, indexed as `AR-TICK-843-01` to `-05` in [accepted risks](../security/accepted-risks.md). The main ones: without the IdP hint a user sees a sign-in prompt, and `nava-web` keeps the bare scope, so a user in two organizations gets 401 on their first brokered sign-in to the first-party app.
