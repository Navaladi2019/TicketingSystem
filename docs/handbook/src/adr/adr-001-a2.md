Status on `main`: **ACCEPTED**, 2026-10-23, approved by the product owner. Amends [ADR-001-A1](adr-001-a1.md) (D9, D6-K) and [ADR-001](adr-001.md) Annex A.2. Normative text: [the A2 record](../../../../docs/adr/ADR-001-A2-f2-system-workflow-reach.md); explainer: [A2-explained.html](../../../../docs/adr/ADR-001-A2-explained.html).

*Paraphrases: "Decision", "D9 additions", "D6-K addition", "R-CORE", "Rejected options", "Consequences and accepted residuals".*

## Problem

Review findings (F2-1 to F2-6) showed that a stolen service certificate could still reach Temporal system workflows, forge task tokens, read other workflows' history, or name non-platform task queues. None is a tenant-to-tenant gap; each needs a stolen certificate.

## Decision

One record in two labelled parts. **Erratum E2** covers cases where A1's wording already required the check and the D9 table left it out. **Amendment A2** adds new rules.

- **D9b+, D9d, D9e, D9f, D9g:** extend the allow-list. Worker polls must not use worker versioning; every task-token API must carry a `t:<tenant>:` workflow id; history reads and core calls must name a `t:<tenant>:` workflow id; shutdown and heartbeat calls may name only platform or sticky-shaped queues.
- **D6-K addition:** the server refuses to start unless token-namespace enforcement is on.
- **R-CORE:** the core builds every workflow id it sends to Temporal from the tenant resolved from the validated token and a key read under row-level security, and never forwards a client-supplied opaque token. This is a code-and-test rule, not an Authorizer rule.
- A drift test lists every field of every allow-listed request, so a Temporal API upgrade that adds a field fails CI until a policy change classifies it.

## Options that lost

Closing F2-1 with a config key; both the rule and the key; comparing namespace ids in the Authorizer; deny-listing system names; a per-tenant certificate for the core; leaving F2-2 and F2-4 as residuals.

## Consequences

I2 is strengthened for the core-to-Temporal path. No new start or signal path (I6 unchanged).

## Accepted risks

| # | Risk | Revisit when |
|---|---|---|
| RS6 | R-CORE is enforced by code and tests, because the Authorizer cannot see inside a history page token. | The first core call to Temporal, any paginating core API, or any path running tenant code. |
| RS7 | Under D9g, one worker pod can still unload a sibling pod's SDK-shaped sticky queue, because the check covers the shape, not the owner. Harmless: sticky dispatch falls back to the normal queue. | Worker certificates become per-pod or per-tenant, or sticky queues gain a tenant meaning. |
| RS2 (widened) | The new D6-K row is checked only at startup, like the rest. | Any runtime write path to dynamic config. |
