## Problem

*Paraphrases: "2. Context".* A replay gate replays every committed workflow history against the current interpreter code, and forbids editing or deleting any history already on `main`. The older rule for retiring an old code arm was to delete the `GetVersion` branch; after that the old histories no longer replay, but cannot be deleted either. The pipeline document marked this as open. A spike also showed that deleting the call is unsafe: old histories replay green, and a production run the query missed would silently run the new arm.

## Decision

*Paraphrases: "1. Decision", "3. Design".*

1. Retire a `GetVersion` change's old arm only by raising `minSupported`; the call itself is never deleted.
2. In the same PR, delete each history that now fails replay with the "removed support of version -1" error, and append one tombstone per file to an append-only manifest.
3. A test enforces this mechanically (rules R-1 to R-8: no edits to histories on the base branch, no deletion without a matching tombstone, the manifest only grows, retired names do not reappear, the call remains with a raised minimum, arguments are literals, and the deleted blob really fails with that error).
4. Approval is human and outside CI: the Technical Architect reviews, the Operator posts the production query evidence, and only the human owner merges a PR touching the manifest.
5. Scope: only the default-version arm.

## Options that lost

*Paraphrases: "5. Options considered and rejected".* Deleting the call; moving retired files to a subfolder; an allow-list in Go code; re-recording histories; enforcing approval through code owners (agent PRs share the owner's GitHub account); running the production query from CI; a 24-hour freshness window for the evidence.

## Consequences

*Paraphrases: "4. Consequences", "8. Rollout and sequencing", "9. Invariant check".* Test code, test data and docs only, with no production code change. It matters at the first `GetVersion` retirement. A missed run blocks on replay instead of running the wrong code.

## Accepted risks

*Paraphrases: "7. What is being accepted".*

| # | Risk | Revisit when |
|---|---|---|
| RS-1 | "Agents never merge a manifest PR" is enforced by process only, not by GitHub. | Agents get their own GitHub identity. |
| RS-2 | The production query is a human-checked fact; a missed run blocks after deploy and recovery is a fix forward. | The first retirement. |
| RS-3 | Only the default-version arm is in scope. | The first need to retire a later version. |
| RS-4 | Whether a reset run's start time falls before the cut-off is not verified, so any reset invalidates the evidence. | Only if resets become routine. |
