## Problem

The scan jobs of `govulncheck.yml` ran `make vulncheck`. Make reads about twenty files, and any of them could change what the scan did while the recipe that `check-ci-steps` pinned still looked the same: the recipe environment, code run while make reads its files, or an edit that applies only when a CI variable matches. The last of these cannot be seen by a check that runs outside the scan job (AR-TICK-1167-01).

## Decision

| # | One line |
|---|---|
| A7.1 | Each scan job runs `go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...` after `actions/setup-go@v6`, with `GOENV=off`, `GOWORK=off`, an empty `GOFLAGS`, `GOTOOLCHAIN=local` and the default proxy settings in the step's `env:`. No step runs `make`. |
| A7.2 | `make check-pins` fails unless the workflow, `Makefile` and `docs/pins.md` name the same govulncheck version, with exactly one version line per scan job. |
| A7.3 | The make targets stay for local use only. The make recipe and environment checks are deleted; a new `check-ci-steps` check fails on any `make` in the workflow. |
| A7.4 | Contract rule 7 also fails on a tracked `vendor/` and on a `go.mod` outside the five known modules and `testdata/`. Rule 9 now says the copy pins the command and its environment, while the module layout still sets what `./...` covers. |
| A7.5 | One scratch workflow run (S4) records the Go version, the empty settings and the build time before the rest of the plan. |
| A7.6 | The plan's last task closes AR-TICK-1167-01. |

## Options that lost

Keep make and keep adding rules; a dedicated pinned makefile; `golang/govulncheck-action`; `go install` then call by absolute path (kept only as fallback).

## Accepted risks

AR-TICK-1140-03 (unchanged): a pull request that edits the workflow and its copy still passes. AR-TICK-1183-01: the `docs`, `tools/navalint` and `tools/workflowcheck` modules are never scanned. AR-TICK-1183-02: a scanned `go.mod` can narrow its own scan with `replace`, `exclude` or `ignore`.
