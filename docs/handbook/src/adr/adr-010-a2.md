## Problem

D7 found "every unit below the caller's" on each request by walking the org tree, then bound every id into the list query. On S31's schema that cost +94 ms at a 1,011-unit region and +200 ms at 10,000 units. It cost 305 ms just to refuse a caller over the 10,000-unit cap. No single SQL shape was fast at every subtree size.

## Decision

| # | One line |
|---|---|
| A2-1, A2-2 | `org_unit_closure` holds live paths only, built from live roots. Groupsync rebuilds it in the same transaction as the tree change, under a per-tenant advisory lock. |
| A2-3 | `records_org_unit` becomes `(tenant_id, org_unit_id, entity_definition_id) WHERE org_unit_id IS NOT NULL`. No other `records` index. |
| A2-4 | U is made `DISTINCT` and canonical on every request. `Allows` is one closure-PK `EXISTS`. `ExpandUnder`, `MaxUnderSet` and the `access_scope_too_large` 500 are deleted. |
| A2-5 | The probe P3 counts up to K\* + 1. The count's region branch is always the capped CC. The page uses C3 (a `MATERIALIZED` CTE) at ≤ K\* and the `OFFSET 0` walk W0 above. A2-5a: a type with N̂_e ≤ K\* skips the probe and uses W0 for both statements. |
| A2-6 | Every shape computes one predicate. The probe changes the SQL text, never the rows. A probe error returns 500, with no fallback. |
| A2-7 | Bounds: about K\* rows at the switch. The certified size is 10,111 live units per tenant: above it an alert fires, and groupsync never refuses a sync. |
| A2-8 | D4: at most 4 distinct `under` start sets per policy, and no nested or duplicate ids. Either is a 422. |
| A2-9 | K\* = clamp(0.8 × √(page × N̂_e), 1,000, 20,000), which is about 3,600 at bench scale. N̂_e comes from a new `entity_record_estimates` table, refreshed hourly per tenant under RLS. |
| A2-11 | R1 is scored on paired wall-clock for the worst persona, a caller whose only grant is `under`, against 150 ms directly. |

## Evidence

The evidence is the A2-12 (a) crossover cells: probe harness, paired wall-clock, floor gate passed.
- C3 and W0 cross at m ≈ 3,650, so c = 0.8.
- At K\*, the worst cell is **+25.5 ms median** for the region-only caller, against +85.4 ms with a fixed K = 1,000. Every other set is ≤ +19.2 ms.
- A rare type at root goes from +71 ms to +7.7 ms with A2-5a.
- The B1 key takes the probe on a mixed-type district from 220 ms to 1.9 ms.
- The capped count takes a region-only caller's count from about 1 s to ≤ 3.2 ms.

These are harness deltas, not budget numbers.

## Residuals

- **A2-R1:** region-only callers at m ≈ K\* may be over 150 ms. TICK-1037 decides; if it fails, the gap goes to the CTO as option (iii).
- **A2-R2:** a dormant subtree defeats W0's bound.
- **A2-R3:** a stale N̂_e. It costs time only.
- **A2-R5:** selective unindexed filters move the crossover. This is the same class as R-006.
- **A2-R6:** a type concentrated outside most of a large S costs about 10 µs per unit: +94 ms at 9,099 units.
- **`AR-TICK-1040-01`** in [accepted risks](../security/accepted-risks.md): latency can reveal, inside the tenant, whether more than K\* records sit under a policy's units.
