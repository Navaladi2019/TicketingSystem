## In plain words

Admins build access rules from named, reusable yes/no tests called **conditions**, for example "I raised it", "it is assigned to my group" or "it is in my region". They combine conditions with AND, OR and NOT into named **policies**, and each policy says who may read or change which tickets. A workflow step can check a policy by its name.

Today's flat rules (story [S10](../stories/s10.md)) cannot be reused and have no OR or NOT. After this ADR, a broken rule is refused when the admin saves it, with a pointer to the bad part; editing one condition updates every policy of that ticket type that uses it in one saved change; the "why can this user see this ticket" screen names the policy and the conditions that decided; and existing rules keep giving the same answers.

## Decision

*Paraphrases: "Decision".* Access stays allow-only and is computed by one planner rendered twice, as a database filter and as a Go check that give the same answers (I5). An access change is a row insert, not code or DDL (I8).

| # | One line |
|---|---|
| D1 | Allow-only: access to an op is the OR of the policies that grant it. No deny rules, no precedence; NOT only inside an expression. |
| D2 | One document per entity type: `{"format": 2, "conditions": [...], "policies": [...]}`. Arrays, so a duplicate name is a 422 and order is kept. `masks` is unchanged. |
| D3 | Closed grammar: `all`, `any`, `not`, `ref`, `member_of`, `cmp`, `shared`, `under`. No function, script or external call. |
| D4 | Save-time checks, in the publish route (422 with a JSON pointer) and in the PL/pgSQL CHECK: refs resolve, no cycle, depth ≤ 8, ≤ 256 leaves per policy, ≤ 64 policies and ≤ 1,024 leaves per document, every id belongs to the tenant. |
| D5 | NULL and invalid differ: a NULL or empty input makes a leaf false; an invalid node voids the whole policy, which grants nothing and is counted. |
| D6 | One planner, two renderings (`Allows`, `CompileRead`); branches per index up to a threshold set by SP-2, then the slower OR form. |
| D7 | `in_my_region`: tombstoned `org_units`, a new `org_unit_members` table, a fixed `records.org_unit_id`; the `under` leaf is `org_unit_id IS NOT NULL AND org_unit_id = ANY(S)` over live units. More than 10,000 ids is a typed 500 and an alert. |
| D8 | The write pipeline sets `org_unit_id` on create from the requester's primary unit; after that it is a stored, masked, audited field. Moving tickets is a workflow step. |
| D9 | Workflow references are `(entity type key, policy name)`, resolved against the current version; a missing name denies and is audited. |
| D10 | The explainer adds `Policy` and `Trace`; a voided policy shows as `invalid`. `RuleID` stays for one release. |
| D11 | One condition language: a node registry marks `sql_safe` kinds, and a build test fails any kind missing a renderer or generator coverage. |
| D12 | Format 1 is converted on read, never rewritten; publish always stores format 2. |
| D13 | Not in this ADR: JSON `data` field conditions, row-dependent masks, deny rules, relationship-based authorization. |

## Options that lost

| Option | Why |
|---|---|
| Tenant-wide condition library, versioned on its own | One edit fans out across many documents; needs a second table, cache and publish path. |
| Deny rules with precedence | Precedence in two renderings is a new way for SQL and Go to disagree. |
| Text language (CEL or a custom DSL) | Puts a parser in the trust path and still needs a SQL translation. |
| Conditions and policies as JSON object keys | `encoding/json` and `jsonb` keep the last duplicate key silently. |
| Closure-table join inside the predicate | Breaks "caller resolved first"; it is the fallback if SP-1 fails. |
| Materialized org path on records, or `ON DELETE SET NULL` | Rewrites records outside the write pipeline (I4) without audit. |
| Hard-deleting org units with the new FK | One ticket on a deleted unit would fail every sync for that tenant. |

## Competitive Gate

**PASS with accepted risk CP-SF-02.** Axis X2 (change cost): composing or changing an access rule becomes one publish, with no code and no DDL. It avoids CP-SN-03 and CP-SF-03 (stored S10 rules are converted on read) and CP-SF-06 (a rule change cannot widen access outside the tenant, and a broken rule grants nothing). It risks CP-SF-02 because D4 adds caps; item 5 of the [ADR-008](adr-008.md) D11 test waits for SP-2. Measured by M-X2, SP-1 and SP-2. Invariants I1–I9 are unchanged; I5 and I8 are strengthened.
