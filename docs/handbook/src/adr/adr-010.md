## In plain words

Admins build a ticket type's access rules from named, reusable yes/no tests called conditions, for example "I raised it", "it is assigned to my group" or "it is in my region". They combine them with "and", "or" and "not" into named policies, and each policy says who may read or change which tickets. A workflow step can test a policy by its name.

When it is done, a broken rule is refused at save with a pointer to the bad part. Editing one condition updates every policy of that type that uses it, in one publish. The "why can this user see this ticket" answer names the policy and the conditions that decided. Existing S10 rules keep giving the same answers.

## Decision

| # | One line |
|---|---|
| D1 | Allow-only. Access to an op is the OR of the policies that grant it. NOT exists only inside an expression, never as a deny rule. |
| D2 | One document per entity type and version: `{"format": 2, "conditions": [...], "policies": [...]}`. These are arrays, so a duplicate name is a 422. The publish, the optimistic version and the audit entry are in one transaction. |
| D3 | A closed grammar: `all`, `any`, `not`, `ref`, `member_of`, `cmp`, `shared`, `under`. There is no function, script or external call. |
| D4 | Save-time checks run in the route (422 with a JSON pointer) and in the database as a backstop. Every `ref` must resolve, with no cycles. Depth is at most 8, with at most 256 leaves per policy, 64 policies and 1,024 leaves per document. Every id must belong to the tenant. SP-2 may lower these caps. |
| D5 | Every leaf has two values: a NULL column or a missing caller makes it false. An invalid node voids the whole policy, which then grants nothing and is counted. |
| D6 | One planner with two renderings (Go `Allows`, SQL `CompileRead`). Index-per-branch lists apply up to an SP-2 threshold, and the OR form is used above it. |
| D7 | `in_my_region`: one recursive query over live org units gives set S, and the leaf is `org_unit_id IS NOT NULL AND org_unit_id = ANY(S)`. Tombstoned units drop out of S, so access fails closed. More than 10,000 ids is a typed 500. |
| D8 | The write pipeline sets `records.org_unit_id` on create, from the requester's primary unit. After that it is stored, masked and audited. Moving a person does not move their tickets. |
| D9 | A workflow names `(entity type, policy)`, resolved against the current version in an activity. A missing name denies, and is counted and audited. |
| D10 | The explainer adds `Policy` and `Trace`. `RuleID` stays for one release. |
| D11 | One condition language. A node registry marks the `sql_safe` kinds, and a build test checks that each has both renderers. |
| D12 | Stored rows are never rewritten. Format 1 is converted on read, and the converter stays while any format-1 row exists. |
| D13 | Not covered: conditions on JSON data fields, row-dependent masks, deny rules, relationship-based authorization. |

## Options that lost

| Option | Why |
|---|---|
| Tenant-wide condition library, versioned on its own | One edit fans out across many documents. It needs a second table, cache and publish path. |
| Deny rules with precedence | Precedence in two renderings is a new way for SQL and Go to disagree. |
| Text language (CEL or a custom DSL) | It puts a parser in the trust path and still needs a SQL translation. |
| Conditions as JSON object keys | `encoding/json` and `jsonb` silently keep the last duplicate key. |
| A closure-table join in the predicate, a materialized org path on records, or hard-deleting org units | Each either breaks "caller resolved first", writes records outside I4, or fails every sync for the tenant. |

## Accepted risks

| # | Residual | Owner | Revisit when |
|---|---|---|---|
| R1 | `ANY(S)` over the list budget for large subtrees | Technical Architect (SP-1) | SP-1 above 150 ms p95 |
| R2 | Caps or the branch threshold block a real policy | Solution Architect | An admin reports one |
| R3 | Group and org-unit changes reach access only at the next sync (10 minutes) | Security & Multi-Tenancy Reviewer | A faster-revocation requirement |
| R4 | Conditions are duplicated across entity types | Solution Architect | More than 3 types share an identical condition |
| R5 | A workflow references a removed policy and denies at run time | Technical Lead | Workflow definitions store policy references |
| R6 | Insert cost of the database checks grows (0.30 ms today) | Postgres & Data Modeling Specialist (SP-2) | Above 5 ms at the caps |
| R7 | A voided policy silently removes access | Technical Lead | `authz_policy_invalid_total` above zero |
| R8 | One user's subtree exceeds 10,000 units | Technical Lead | `groupsync_org_subtree_max` near the cap |

## Competitive Gate

**PASS with accepted risk CP-SF-02.** Axis X2 (change cost): composing or changing an access rule becomes one publish, with no code and no DDL. Stored S10 rules are converted on read, so none needs review (CP-SN-03, CP-SF-03). The D4 caps risk repeating CP-SF-02, but they are published, the same at every tier, and refused at save with a typed 422. How large they are waits for SP-2.
