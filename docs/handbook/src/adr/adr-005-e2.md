Erratum to [ADR-005](adr-005.md) section 3.5 (the `grow` sentence). Normative text: [the E2 record](../../../../docs/adr/ADR-005-E2-grow-refused-when-digit-touches-seq.md); explainer: [E2-explained.html](../../../../docs/adr/ADR-005-E2-explained.html). The page is `delivered` because the erratum is accepted and the compiler rule it describes is already built ([S17](../stories/s17.md)); the admin API that returns the error ships with S18.

*Paraphrases: "What was wrong", "Correction".*

## Problem

ADR-005 section 3.5 allowed `grow` when every variable-width token is *followed* by a literal outside its character set, or ends the number. That only looks at what comes after `{seq:N}`, so `{prefix}{yy}{seq:3}` passed. The number-format compiler (`unambiguous()` in `internal/records/numbering/template.go`) also refuses a digit directly *before* `{seq:N}`. Text and code disagreed, and the difference is visible to anyone publishing a format.

## Decision

- **The code's rule is the rule.** A date part (`{yyyy}` `{yy}` `{MM}` `{dd}`), a `{field:…}` token, or a literal ending or starting with a digit, directly before or after `{seq:N}`, makes `grow` fail at publish with `number_format_invalid` (422), `field: overflow`, the position of `{seq:N}`, and a fixed reason ("grow needs a non-digit before {seq:N}; use refuse", or "after").
- **Still valid with `grow`:** the default `{prefix}{seq:7}`, `{prefix}-{seq:4}`, `{prefix}-{yyyy}-{seq:4}`, `{prefix}/{yy}/{seq:2}/{MM}`.
- **Now need `refuse`:** `{prefix}{yy}{seq:3}`, `{prefix}-{yyyy}{MM}{seq:4}`, `{prefix}-{yyyy}{MM}{dd}{seq:2}`, `{prefix}2{seq:1}`.
- It is a **readability** rule (the number can be split without the template), not what keeps numbers unique; uniqueness across epochs is `Disjoint`'s job.
- The S18 admin API adds `number_format_invalid` to `api/errors.yaml`; the admin UI suggests `refuse`.
- Stricter now because relaxing a publish rule later is safe and tightening it after tenants publish formats is not. No format has been published yet.

## Rejected

Relaxing the code to "after only" (`INC261000` cannot be read without the template), and dropping the `grow` rule for S17 (the "after" half matters for uniqueness once `{field:…}` compiles in S19).

## Accepted consequence

Not a security or tenant risk. A date-then-sequence format must use `refuse`, so once its counter fills the width within one scope, creates of that type fail with `number_space_exhausted` (409) until an admin publishes a wider format; the 90 % alert warns first. A separator (`{prefix}-{yyyy}{MM}-{seq:4}`) makes `grow` valid again.

## Evidence

The Technical Architect's spike ran five digit-adjacent templates for 1,259,690 allocations each, past their width, with 0 clashes; `TestDisjointProperty` and `FuzzDisjoint` pass.
