## What it changes

ADR-001 said the Temporal Authorizer should deny a continue-as-new command "that changes the workflow id". That clause cannot fire, because a continue-as-new command has no workflow-id field: Temporal always keeps the id.

## Decision

The clause is replaced by rules that are strictly stronger. For a worker's `RespondWorkflowTaskCompleted`, the Authorizer:

- denies the response, and alerts, if the task token does not decode or its workflow id has no `t:<tenant>:` prefix;
- denies start-child, signal-external and cancel-external commands whose target has another tenant's prefix (or none) or another namespace;
- denies continue-as-new whose `nava-tenant` header is missing or differs from the task token's prefix, or that sets a cron schedule;
- denies every command type not on the written allow-list.

## Consequences

The header check is defence in depth, because the worker sets the header; the real controls are the namespace check and deny-unlisted. Annex B row CI-6 is updated to match. I6, I7 and D22 are unchanged.

## Accepted risks

None recorded in this erratum.
