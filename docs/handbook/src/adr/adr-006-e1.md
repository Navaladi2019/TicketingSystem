## Problem

D9 says the snapshot barrier waits on `pg_snapshot_xip` of one `pg_current_snapshot()`. A snapshot's `xmax` is one past the highest *completed* xid, and xip lists only in-progress xids below `xmax`. When the writer holding the newest assigned xid is still running, `xmax` equals that xid and xip does not list it, so the barrier does not wait for it. That writer's record can then reach `ready` with no side row: the CI-5 R1 failure D9 exists to prevent. Reproduced twice: `1869:1869:` in the TICK-745 integration run, and `731:731:` in the Solution Architect's spike on PG 16.10.

## Decision

- **E1-1 Wait set = xip ∪ in-progress xids in `[xmax, M)`.** In one transaction the activity takes `pg_current_snapshot()` and then a fence xid `M = pg_current_xact_id()`, and rolls back. The range is usually small, but subtransactions make it unbounded (the TA spike measured 100,001 xids for one writer holding 100k savepoints), so the heartbeat may keep the bounds (`xip`, `xmax`, `M`) instead of the list. Waiting on xids assigned between the two statements is conservative, never wrong. Implemented in `internal/fieldindex/backfill/activities.go` (`snapshotSQL`, `fenceSQL`), PR #738.
- **E1-2 READ COMMITTED is a precondition.** Xids above `M` are safe only because records writers run at READ COMMITTED and the D4 trigger is an AFTER ROW trigger (the writer's xid exists before it runs) that reads the registry with a fresh statement snapshot. No `records` write path may raise its isolation level, and operators must not set `default_transaction_isolation` above READ COMMITTED for `nava_app` or `nava_worker` (same rule as ADR-005-E1).
- **E1-3 Regression test.** This is a direct newest-xid test: xmax equals the writer's xid and xip is empty, the barrier does not return until the writer commits, and the test fails with the fence removed. It is `TestBarrierWaitsForTheNewestXID` in PR #743 (TICK-976): red with the fence removed, green with it.
- **E1-4 Removal uses the same barrier** (D11 step 2 via `fieldindex.Barrier`, TICK-750).
- **E1-5 The precondition fails closed.** The first statement of `record_field_values_sync()` raises a class-25 SQLSTATE naming ADR-006-E1 when `transaction_isolation` is not `read committed`. It ships as a follow-up migration with an integration test (RR insert refused, RC insert accepted).
- Not changed: D4, D10, D11, R11; I1, I4, I7, I8; no new grant, still `nava_worker`; no tenant data in the wait set, heartbeat or metric.

## Options that lost

Keep xip only (proven to miss the newest writer). Scan `[xmin, M)` (grows with the oldest open transaction). Read `pg_stat_activity.backend_xid` (needs `pg_read_all_stats`, and still needs a fence). Have the trigger take a lock that the flip waits on (a lock on every records write; ADR-006 D4 already rejected write-path coordination).
