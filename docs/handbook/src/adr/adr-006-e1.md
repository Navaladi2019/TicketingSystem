## Problem

D9 says the snapshot barrier waits on `pg_snapshot_xip` of one `pg_current_snapshot()`. A snapshot's `xmax` is one past the highest *completed* xid, and xip lists only in-progress xids below `xmax`. When the writer holding the newest assigned xid is still running, `xmax` equals that xid and xip does not list it, so the barrier does not wait for it. That writer's record can then reach `ready` with no side row: the CI-5 R1 failure D9 exists to prevent. Reproduced twice: `1869:1869:` in the TICK-745 integration run, and `731:731:` in the Solution Architect's spike on PG 16.10.

## Decision

- **E1-1 Wait set = xip ∪ in-progress xids in `[xmax, M)`.** In one transaction the activity takes `pg_current_snapshot()` and then a fence xid `M = pg_current_xact_id()`, and rolls back. The range normally holds a few xids; waiting on ones assigned between the two statements is conservative, never wrong. Implemented in `internal/fieldindex/backfill/activities.go` (`snapshotSQL`, `fenceSQL`), PR #738.
- **E1-2 READ COMMITTED is a precondition.** Xids above `M` are safe only because records writers run at READ COMMITTED and the D4 trigger reads the registry with a fresh statement snapshot. No `records` write path may raise its isolation level, and operators must not set `default_transaction_isolation` above READ COMMITTED for `nava_app` or `nava_worker` (same rule as ADR-005-E1).
- **E1-3 Regression test.** This is a direct newest-xid test: xmax equals the writer's xid and xip is empty, the barrier does not return until the writer commits, and the test fails with the fence removed. It is tracked in TICK-976.
- **E1-4 Removal uses the same barrier** (D11 step 2 via `fieldindex.Barrier`, TICK-750).
- Not changed: D4, D10, D11, R11; I1, I4, I7, I8; no new grant, still `nava_worker`; no tenant data in the wait set, heartbeat or metric.

## Options that lost

Keep xip only (proven to miss the newest writer). Scan `[xmin, M)` (grows with the oldest open transaction). Read `pg_stat_activity.backend_xid` (needs `pg_read_all_stats`, and still needs a fence). Have the trigger take a lock that the flip waits on (a lock on every records write; ADR-006 D4 already rejected write-path coordination).
