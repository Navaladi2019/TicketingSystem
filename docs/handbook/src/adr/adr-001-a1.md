Status on `main`: **ACCEPTED**, 2026-10-20, approved by the product owner. Amends [ADR-001](adr-001.md) section 3 (pin block), R7 (revisit trigger) and Annex A.2 (allow-list). Normative text: [the A1 record](../../../../docs/adr/ADR-001-A1-temporal-server-1-29-7-workload-allow-list.md); explainer: [A1-explained.html](../../../../docs/adr/ADR-001-A1-explained.html).

*Paraphrases: "Decision", "D6-K: guarded keys at v1.29.7", "D9: workload allow-list", "Rejected options", "Consequences and accepted residuals".*

## Problem

The vulnerability gate flags the pinned Temporal server version (the vulnerable code path does not exist on that version, but the gate must be green). Separately, a live spike showed a relay certificate starting a Temporal system batch workflow that terminated another tenant's workflow, on every version.

## Decision

1. Move the Temporal server and API pins to v1.29.7 / v1.53.0 (the SDK stays on its pin). The database schema is updated before the new binary starts.
2. No vulnerability-gate exception: the gate must report zero findings.
3. **D6-K:** the server refuses to start if any of a list of dynamic-config keys breaks its rule (for example schedules, the batcher and cross-namespace commands must be off).
4. **D9:** a request that names a workflow type, a task queue or a workflow id is allowed only if every such field is on an allow-list. There is no deny-list. It covers relay starts and signals, worker polls (including the sticky-queue shape) and worker commands.
5. The R7 revisit trigger is widened to any Go vulnerability advisory against the pinned server module.

## Options that lost

Stay on the old version with a time-boxed exception; versions 1.29.5, 1.29.6, 1.30.8 and 1.31.4; a backport; relying on network topology; closing the hole by configuration only; a deny-list of `temporal-sys-*` names (everything Temporal adds is allowed until someone notices).

## Consequences

I2 is upheld only with D9. Every new workflow type or task queue now needs a policy change with Security review and an image rebuild.

## Accepted risks

RS1 (support horizon of 1.29 unknown), RS2 (D6-K checks only at startup), RS3 (SDK against this server proven only by one CI check), RS4 (switching off system features could break an internal workflow), RS5 (policy PR cost per new workflow type). Follow-ups F1, F2 and E4 are listed in the original and are not part of A1; [A2](adr-001-a2.md) closes F2.
