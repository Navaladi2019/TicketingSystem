              ADR-001-E3: the onboarding role reads its own tenant row

              Status on main: ACCEPTED, 2026-10-25, approved by the product owner. Erratum to ADR-001 Annex A.3, onboarding row. Normative text: the E3 record; explainer: E3-explained.html.

              Paraphrases: "Decision", "Context", "Consequences", "Rejected options", "Accepted residual".

              Problem

              Annex A.3 said the onboarding role may SELECT "its own provisioning row". The shipped policy has no state test, and a state test cannot be added: activating a tenant is an UPDATE, and PostgreSQL applies the SELECT policy to the new row too, so a provisioning-only policy rejects the switch to active (error 42501). The idempotency check also needs to read a tenant that may already be active.

              Decision

              The words change; the code does not. The clause now reads: SELECT on its own row (the tenant of its transaction, in either state). No migration, grant or policy changes.

              Options that lost

              Adding state = 'provisioning' to the policy (breaks activation); the same with an unfiltered UPDATE (works only until a statement names a column); a second permissive policy for active rows (identical to the shipped policy, with more surface).

              Consequences

              Text now matches code. A test pins that the role sees only its own tenant, in both states, and nothing with no tenant set.

              Accepted risks

              RS8: the onboarding role bound to tenant A can read A's active row (id, state, request hash, created time), nothing else. Severity Info. It holds only while the caller cannot choose the tenant id, which the server derives itself.
