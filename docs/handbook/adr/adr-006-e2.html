    Handbook / adr / ADR-006-E2: CountBudget 170 ms, the count runs without parallel workers, and the leak check uses pg_ls_tmpdir()

    Summary. The normative text is the linked docs/adr/ADR-006-E2-count-budget-170-serial-count.md.

    In progress: not on main yet

    ADR-006-E2: CountBudget 170 ms, the count runs without parallel workers, and the leak check uses pg_ls_tmpdir()

    Status: ACCEPTED, rev 1, 2026-11-22. The Solution Architect gave the verdict on TICK-1094 after the Technical Architect's rev 0 critique, which had no blocking items. Findings 3 to 6 were taken in rev 1. Nothing was contested, so no CTO tie-break was needed. Erratum to A2 of ADR-006. Normative text: the E2 record. Explainer: E2-explained.html. Evidence: s-a2-cancel, runs 5 and 6 of spike S-A2-cancel (TICK-1083, PR #851). The page is in-progress because the change is not on main yet. It lands on the S21 branch TICK-1046/count-budget through Plan ADR-006-E2.

    Paraphrases: E2-1 to E2-5, "Interim".

    Problem

    A2 set CountBudget at 200 ms on the assumption that a count cancelled by statement_timeout stops within 15 ms. Spike S-A2-cancel found two shapes where it doesn't. A count that has spilled to temp files overshot by up to +45.9 ms at 8 clients (run 5; +27.8 ms in run 6, which passed its host gates). A count whose plan has a Gather overshot by +71.2 ms (run 6, gate-flagged). The cancel waits for the workers to stop. A2-8 (3a)'s fail rule says to re-derive A2-2 with the measured overshoot as an extra term.

    Decision

    • E2-1 CountBudget = 170 ms. 350 − 94 − 6 − 35 − 40 = 175, rounded down. The 40 ms is run 5's +45.9 ms less the 6 ms of round trips A2-2 already counts. It is a conservative upper estimate: run 5's spill cell was not gated, and run 6's clean figure would give 190 ms. Erring this way only raises the unknown share. A gated spill-only rerun is the lever if R13 or R14 fires.
    • E2-2 The budgeted count runs without parallel workers. The savepoint Exec becomes SAVEPOINT list_count; SET LOCAL statement_timeout = '<ms>'; SET LOCAL max_parallel_workers_per_gather = 0. It is still one round trip. ROLLBACK TO SAVEPOINT list_count undoes both settings, so the page statement keeps the server's settings. It is conditional on A2-8 (3e).
    • E2-3 Leak check. pg_ls_tmpdir() lists no pgsql_tmp files after the run and 60 s after. temp_files is reported only to show that a spill happened.
    • E2-4 A2-8 additions. (3c) checks that the worker setting is 0 inside the savepoint and back to its earlier value after ROLLBACK TO, and that the next pooled transaction has the default. (3e) compares arm A (no workers, 170 ms) with arm B (server settings, 140 ms) in ABBA blocks of 15 s at 8 clients, with host gates around each block. The cells are the kit's band (ii) count and a50, pk = 3. Pass: A's unknown share ≤ B's + max(1 point, 2 × SE), and A's band (ii) p95 ≤ 350 ms. A plan check shows no Gather under A and a Gather under B. Fail: E2-2 falls away, and a parallel-only rerun sets the term (about 140 ms).
    • Interim: S21's PR #827 ships 140 ms, or waits for E2's plan. 170 ms ships only together with E2-2, after (3e) passes.
    • Not changed: the 57014 contract, total_state, the 1,001 cap, RLS, the page statement, A2-4 and A2-6. I1 to I9 are unchanged.

    Options that lost

    Keep 200 ms (A2's rule is mechanical, and the clean run confirmed the spill). Price the parallel term into every count, at about 140 ms (that is the fallback). Use run 6's clean spill figure alone, at 190 ms (it is one run). Turn off parallel query server-wide or for nava_app (that would change unmeasured page queries). Raise work_mem for the count (memory per connection would be unbounded under load).
