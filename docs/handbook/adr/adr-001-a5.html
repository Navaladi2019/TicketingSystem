              ADR-001-A5: a cascade cycle suppresses the re-start

              Status on main: ACCEPTED (revision 1), 2026-10-31, accepted by the Technical Lead under sign-off the product owner delegated for this amendment only. Amends ADR-001 I9 and Annex B CI-10. Normative text: the A5 record; explainer: A5-explained.html.

              Paraphrases: "Decision", "Context", "Consequences", "Rejected options", "Accepted residuals", "Recorded dissent".

              Problem

              I9 said the pipeline rejects a cycle (the same origin seen again on the same record). That rejects a normal workflow: a user creates a record, a definition starts, and its own "update this record" step writes the record again under the same origin.

              Decision

              A workflow definition starts at most once per (tenant, origin, record). The check runs when the pipeline is about to start a workflow, not when it writes. On a repeat the start is suppressed, the write still commits, and one audit row is recorded. Every write made by a workflow is one level deeper than the delivery that caused it, so signals between running workflows also hit the depth limit, which is unchanged.

              Mechanics (A5-1 to A5-7): the check lives in the event sink inside the triggering write's transaction; a new tenant table cascade_start holds the key; a depth-0 write always mints an origin id; a compiler-enforced claim token is required to enqueue a start; causation is carried through starts and signals.

              Options that lost

              Keep the old I9 text; check on writes with a trigger id (the Principal Software Engineer's proposal); reject the write on a hit; a unique index on the outbox; an advisory lock; stamping every workflow write with the start's causation.

              Consequences

              Starts are idempotent per (tenant, origin, record, definition). Cascades terminate. One small row is kept per workflow start, indefinitely in the first milestone.

              Accepted risks

              RS-A5-1: a definition that legitimately needs to run twice on one record in one origin cannot. RS-A5-2: signal ping-pong between open runs is bounded by the depth limit, not the start key. RS-A5-3: a stolen worker certificate could forge a lower depth, which is already inside ADR-001 R8.

              Recorded dissent: the Principal Software Engineer proposed carrying the trigger on writes; the CTO declined it as unnecessary.
