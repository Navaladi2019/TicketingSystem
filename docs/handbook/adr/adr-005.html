            ADR-005: record numbering

            Status on main: ACCEPTED, 2026-11-10, by the Solution Architect after the Technical Architect's critique and CTO rulings; no dissent. The ADR is accepted as a whole, but only part of it is built (see "What is on main"). Normative text: ADR-005-record-numbering.md; explainer: ADR-005-explained.html. Supporting material: rfc/, spikes/. Delivery plan: plan-adr-005.md.

            Each section names the ADR heading it paraphrases.

            What is on main

            Part of the ADR State
            Per-type numbering_mode (gaps default, gapless) on entity definitions, and the allocator for both modes (story S10) Delivered on main.
            Scoped counters (scope_key on record_counters, expand then contract migrations), release R1 (story S17) In progress, not on main.
            Number format tables, links to entity types, epochs, the admin API, formats rendered by the allocator, mandatory counter purge, and the contract migration (story S18) In progress, not on main.
            Field tokens (enum properties), immutable-field marker, coupled mask publish (story S19) In progress, not on main.
            Plugin-authored formats (story S20) Planned, parked until the plugin principal condition is met.
            Plugins that run code per create, or own the counter Deferred (per-create) and rejected (counter ownership).

            Until the scoped counters and formats ship, every type numbers with today's format, the type's prefix followed by seven digits, on the one counter row per tenant and type.

            Problem

            Paraphrases: "Context". Every record gets a human-facing number taken inside the create transaction, which keeps the counter row locked until the create commits. With 8 clients creating the same type in one tenant, counter wait p95 was 237 to 310 ms and create p95 264 to 408 ms against a 50 ms target. Tenants also want formats such as monthly or daily resets, or per-branch counters, and the format was fixed in code.

            Decision

            Paraphrases: "Decision", "2. The allocator".

            • Allocate in its own tiny transaction (L2s) on a dedicated allocator pool, after authorisation and validation and before the create transaction, with synchronous_commit off for that transaction only. This is the path for gaps types, the default. A create that fails after allocation leaves a hole; gaps are never reclaimed.
            • gapless types take their number last, inside the create transaction (L1), so a rolled-back create gives its number back. The 50 ms 8-client target is waived for those types only.
            • Both paths upsert the same counter row, so changing a type's mode cannot produce a duplicate number; the change applies to creates that start afterwards.
            • Why L2s cannot put one number on two records: a record's synchronous commit flushes all earlier WAL, including the counter advance, so a crash can lose only advances whose numbers never reached a committed record.
            • Number formats (planned, S17 to S19): declarative templates that start with the type's {prefix}, with exactly one {seq:N}, date parts, and enum field codes; versioned tenant metadata linked to entity types by pinned version.
            • Scoped counters (planned): record_counters gains scope_key and a period end, with an expand, deploy, contract migration. The default format keeps today's counter, so no existing number is migrated.

            Options that lost

            Paraphrases: "1. Options considered", "6. Plugins". Keeping the counter lock until commit (misses the target); allocating on the main pool before authorisation (a caller with no create permission could advance a counter); cached blocks of numbers (large gaps on restart, kept as a trigger for very hot scopes); assigning the number after commit; a plugin that owns the counter or runs inside the lock (rejected, I8).

            Accepted risks

            Paraphrases: "8. Accepted risks".

            Id Risk
            AR-TICK-653-01 (Low) Numbers issued before a field was masked keep showing that field's code.
            AR-TICK-653-02 (Low) A per-scope sequence reveals volume per scope, within the tenant only.
            AR-TICK-653-03 (Low) The no-duplicate guarantee assumes WAL replays as a prefix; logical replication on record_counters reopens the ADR.
            AR-TICK-653-04 (Info) The allocator pool adds 4 connections per API replica.
            (product) Gaps on gaps types after failed creates or a crash. A tenant with a legal gapless requirement sets numbering_mode = gapless.

            Still owed

            Paraphrases: "10. Still owed". A one-client create over HTTP at or under 50 ms on a quiet host, and the matching budget rows.
