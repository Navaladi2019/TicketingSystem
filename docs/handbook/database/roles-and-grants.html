    Handbook / database / Roles and grants

    Roles and grants

    db/grants.yaml is the only place a privilege is granted. Two jobs read it: db-roles, as the bootstrap superuser, creates each role with exactly the attributes listed (always NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS) and revokes any membership; migrate, as nava_migrator, grants what each role lists and revokes, and logs, anything else on an object it owns, PUBLIC included. The database itself starts with REVOKE ALL ... FROM PUBLIC (00001_global_revokes.sql).

    A grant decides which columns a role may touch. Row-level security decides which rows: every table is under FORCE ROW LEVEL SECURITY, so a grant here reaches only the rows its policies allow.

    Column lists matter. UPDATE never includes a key or a column that is set once at insert, so a record's number or a group's identity provider id cannot be rewritten. Only nava_audit_reader may read audit_log.diff and diff_salt (ADR-004-A1).

    Infrastructure exceptions

    Name Object Security definer Granted to Reason
    pgbouncer_get_auth pgbouncer.get_auth(text) true pgbouncer_auth PgBouncer's auth_query reads pg_shadow, which only a superuser can. The function returns a row only for roles with pgbouncer_login: true, and never for a superuser, BYPASSRLS or REPLICATION role.

    Audited and exempt tables

    Every tenant table is either audited, with a commit-check trigger that makes a write fail unless it wrote its audit entry in the same transaction, or exempt with a reason (db/audited-tables.yaml, ADR-004 R12). The gate fails on a table that is neither.

    Table Status Writer roles or reason Subject type Trigger attached
    acl_versions audited nava_app, nava_worker acl_policy true
    entity_definition_versions audited nava_app, nava_onboard entity_definition true
    entity_definitions audited nava_app, nava_onboard entity_definition true
    record_shares audited nava_app, nava_worker record false
    records audited nava_app, nava_worker record true
    audit_chain_head exempt Chain state (R14). A seal is visible in the sealed entries; reseed and export write their own audit entries (R17, R19). - -
    audit_log exempt The audit log itself (ADR-004 decision 1); R10 and R11 guard its writes. - -
    cascade_start exempt Cascade start key (A5). A suppressed or rejected cascade is audited as a cascade_key entry by the pipeline (ADR-004-E1). - -
    group_members exempt Mirror of the identity provider written by group sync (T16). R2 has no subject type for it (I8). - -
    groups exempt Mirror of the identity provider written by group sync (T16). R2 has no subject type for it (I8). - -
    idempotency_keys exempt HTTP replay cache; the write it replays is audited. - -
    org_units exempt Mirror of the identity provider written by group sync (T16). R2 has no subject type for it (I8). - -
    outbox exempt Start transport (ADR-001 D22); the write that queues a start is audited, the relay's dispatch columns are bookkeeping. - -
    pending_invite exempt Onboarding invites. R2 has no subject type for them (I8). - -
    principals exempt Mirror of the identity provider written by group sync (T16); Keycloak holds the source and its event log. R2 has no subject type for it (I8). - -
    record_counters exempt Record-number counter (D-3-9); the record insert that takes the number is audited. - -
    record_write_keys exempt Dedupe index of a write that is already audited (PLAN-005 D-5-3). - -
    tenant_admin_group exempt Pointer to the tenant's admins group, set once by onboarding. R2 has no subject type for it (I8). - -
    tenant_auditor_group exempt Pointer to the tenant's auditors group, set once by onboarding. R2 has no subject type for it (I8). - -
    tenant_email_domain exempt Onboarding's email-domain claims. R2 has no subject type for them (I8). - -
    tenant_identity_binding exempt Onboarding's binding to the identity provider. R2 has no subject type for it (I8). - -
    tenants exempt Tenant lifecycle, written by onboarding. R2 has no tenant subject type; the epic that audits onboarding registers one (I8). - -
    workflow_ref exempt Workflow bookkeeping for a start the audited write queued; holds no record or configuration content. - -
