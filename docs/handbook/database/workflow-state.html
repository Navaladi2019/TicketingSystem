    Handbook / database / Workflow state

    Workflow state

    Two small tables track workflow starts:

    • workflow_ref: one row per start queued in the outbox, linking the outbox row to its record. The final activity sets closed_at, and nava_purge deletes rows closed more than 30 days ago.
    • cascade_start: the start key of a cascade (ADR-001-A5). A write caused by a workflow carries the origin of the chain that caused it. A definition starts at most once per (tenant, origin, record): the start claims its row with INSERT ... ON CONFLICT DO NOTHING, so a cycle cannot start the same workflow twice. It is insert-only.

    Both are exempt from the audit log, because the write that queued the start is audited.

    Tables

    cascade_start

    Kind: table. Row-level security: enabled true, forced true. Primary key: tenant_id, causation_origin_id, record_id, definition_id.

    Audit: exempt from the audit log: Cascade start key (A5). A suppressed or rejected cascade is audited as a cascade_key entry by the pipeline (ADR-004-E1).

    Column Type Null Default
    tenant_id uuid no -
    causation_origin_id uuid no -
    record_id uuid no -
    definition_id uuid no -
    outbox_id uuid no -
    created_at timestamp with time zone no now()
    Foreign key Columns References On delete
    cascade_start_record_fkey tenant_id, record_id records (records) (tenant_id, id) NO ACTION
    cascade_start_tenant_fkey tenant_id tenants (tenancy) (id) NO ACTION
    Index Method Columns Include Predicate Design note
    cascade_start_pkey (unique) btree tenant_id, causation_origin_id, record_id, definition_id - - -

    Policies with exactly the tenant predicate on tenant_id (RLS): cascade_start_insert (INSERT, nava_app, nava_worker), cascade_start_select (SELECT, nava_app, nava_worker).

    Grants (db/grants.yaml, roles and grants): nava_app SELECT; nava_app INSERT; nava_worker SELECT; nava_worker INSERT.

    workflow_ref

    Kind: table. Row-level security: enabled true, forced true. Primary key: tenant_id, outbox_id.

    Audit: exempt from the audit log: Workflow bookkeeping for a start the audited write queued; holds no record or configuration content.

    Column Type Null Default
    tenant_id uuid no -
    outbox_id uuid no -
    record_id uuid no -
    kind text no -
    created_at timestamp with time zone no now()
    closed_at timestamp with time zone yes -
    Foreign key Columns References On delete
    workflow_ref_record_fkey tenant_id, record_id records (records) (tenant_id, id) NO ACTION
    Index Method Columns Include Predicate Design note
    workflow_ref_pkey (unique) btree tenant_id, outbox_id - - platform-tables, purge-indexes
    workflow_ref_purge_closed btree closed_at - closed_at IS NOT NULL platform-tables, purge-indexes
    workflow_ref_record btree tenant_id, record_id, kind, created_at - - platform-tables, purge-indexes

    Policies with exactly the tenant predicate on tenant_id (RLS): workflow_ref_insert (INSERT, nava_app, nava_worker), workflow_ref_select (SELECT, nava_app, nava_worker), workflow_ref_update (UPDATE, nava_worker).

    Policy Kind Type Command Roles Using Check
    workflow_ref_purge allow-list permissive DELETE nava_purge (closed_at < (now() - '30 days'::interval)) -
    workflow_ref_purge_select allow-list permissive SELECT nava_purge (closed_at < (now() - '30 days'::interval)) -

    Grants (db/grants.yaml, roles and grants): nava_app SELECT; nava_app INSERT; nava_purge SELECT (tenant_id, outbox_id, closed_at); nava_purge DELETE; nava_worker SELECT; nava_worker INSERT; nava_worker UPDATE (closed_at).
