# I5 agreement suite: SQL list predicate vs Go check (P3-32, P11-10, P11-18)

PLAN-003 P3-32 (TICK-617), story S10 (TICK-336). This proves ADR-001 I5 for the record ACL: for every policy, principal and row, `authz.Allows(pol, p, "read", r)` is true exactly when `SELECT … WHERE <authz.CompileRead(pol, p)>` returns `r`.

## Scope

- **Generator** (`internal/tenancy/isolation/i5_gen_test.go`, no build tag). It builds one tenant with 6 users, 3 outsider principals, 5 groups and 2 outsider groups. It also adds a decoy principal that has a group's id and a decoy group that has a user's id. There are 160 records. Requester, assignee and assignment group can each be NULL. Each record has 0 to 3 shares, which can name anyone, outsiders and decoys included.
- **Policies.** Each run has 500 policies. Each policy has 1 to 4 rules over every `Subject` kind and every `Cond` form: state and uuid literals, `self`, `my_groups`, write-only and empty op sets. Malformed conditions are included too: unknown column, `ne`, a bad uuid, eq with 2 values, and a caller reference with values. Nil and empty policies also appear.
- **Principals.** Each policy is checked against 50 principals. Some have no id. Some are in no group. Some are the decoy principal or members of the decoy group.
- **`Row.SharedWith`** follows A1's pair-matched rule: a user share for the caller's id, or a group share for one of the caller's groups. A caller with no id gets no shares. The database holds every share, so a compiler that ignores the pair or the caller admits rows the Go check does not.
- **Route generator** (`internal/tenancy/isolation/i5_route_gen_test.go`, no build tag; TICK-900). One entity type, `iso_et_i5r`, in tenant A with three schema versions: v1 has `prio`, `tag` (strings), `kind` (integer) and `cost` (number, masked per case), v2 adds `"default": "low"` to `prio` (`NeedsBackfill`; nothing backfills old rows, so they read the default), and v3 flags all four `x-nava-filterable` (TICK-752). v3 is published after the records are written, and the real `FieldIndexBackfill` brings each field to `ready` before any filter runs; the run checks that the four fields were `backfilling`, end `ready` at 100, and hold one side row per record whose stored value coerces. 48 records plus two twins are written past the API under `schema_version` 1 or 2, so each data field takes every shape an older row can have: present, JSON `null`, absent and defaulted on read (`prio`), absent with no default, and a different JSON type (`kind` stored as a string in a v1 row; the publish route refuses a type change as Breaking, so such rows come only from a write that bypassed validation). 24 policies (the agreement generator's rules, minus those `acl_versions`' shape CHECK refuses) × 6 callers, each with 5 random `eq`/`in` filter requests on data and fixed fields and one paged list with a random sort and page size.
- **Format-2 generator** (`internal/tenancy/isolation/i5_format2_gen_test.go`, no build tag; PLAN-011 P11-10, TICK-942). It uses the same world and seed. There are 300 documents × 50 principals. Each document has 0 to 4 named conditions and 1 to 4 policies. Trees go up to depth 4 and use every S30 node kind: `all`, `any`, `not`, `ref`, `member_of`, `cmp` and `shared`. Policies share refs. About 6% of leaves are `under` (S31, TICK-950): the caller's units, or one or two of the tenant's units, live, tombstoned, below a tombstoned one, or an id that is no unit. The generator also writes nodes that void their policy: a node with no kind, an empty `all`, a malformed `cmp`, a ref to a missing name, a duplicate condition name, and self or forward refs that form a cycle. Each document also has a previous version of its conditions (same names, other exprs) for the `ref_previous_version` mutant. Some callers have no id, some are in no group, and some have no id but are in groups.
- **Org tree** (`orgTree`, `drawTree` in `i5_gen_test.go`; TICK-951 P11-18, ADR-010 D7). Each seed draws its own tree: 1 to 3 roots, each unit 0 to 3 children down to depth 4, a non-root unit tombstoned at 15%, at most 40 units. A draw that lacks a depth-4 chain, a tombstoned unit with a live descendant, or a live unit (no tombstoned ancestor) with a live child is drawn again from the same stream, so a seed still replays one tree. `Users[i]` is in `i mod 4` live units, so every seed has callers in 0, 1, 2 and 3 units; `org_unit_members` references live units only, but a live unit below a tombstoned one counts. 20% of records have a NULL `org_unit_id`. Every seed also puts `Users[1]` in a unit P and records 0 to 7 in a live child of P: without it, 2 of 12 seeds had no case where `under_direct_only` changes a row. The tree is drawn from a stream seeded by the tenant id, so the S10 draws are unchanged.
- **Oracles** (`i5_format2_oracle_test.go`, no build tag). They do not call the planner. `i5Reference` evaluates a format-2 document from ADR-010 D5: two-valued leaves and plain NOT. A policy is voided by any invalid node, an unresolved or cyclic ref, or a cap exceeded after expansion. `i5S10Allows` is the S10 meaning of format-1 rules, as main evaluated them before S30 (D12). `Allows`, `CompileRead` and `ReadBranches` render one plan, so a planner bug moves all three together, and the SQL-vs-Go check alone cannot see it.
- **Cap cases** (`i5CapCases`, SP-2's caps from ADR-010-A1):
  - A ref chain of depth 8 after expansion (valid) and depth 9 (void).
  - A shared condition reached 8 times, for 128 leaves (valid) and 129 (void). With its leaves inside an `all`, the same shape gives 119 (valid) and 136 (void).
  - 64 policies holding 128 leaves in all (valid). This is past the 16-branch threshold, so the list path falls back to `CompileRead`.

  Publish and the database CHECK refuse a document one past the document caps (TICK-939, TICK-940), so their tests cover that case.
- **Database half** (`i5_agreement_isolation_test.go`, `TestI5Agreement`). It seeds the world as the superuser in one transaction. It then runs `SET LOCAL ROLE nava_app` with the tenant set, and runs one query per policy, with one `UNION ALL` arm per principal. Each arm has its own `CompileRead` predicate, numbered after the arms before it, so `argBase` is exercised too. The transaction is rolled back, so tenants A and B keep their seed and the deferred commit checks never run.

## Report rows (`isolation-report.md`, case I5)

| Row | What fails it |
|---|---|
| I5 agreement | Any case where the two sides disagree: the report row shows the seed, policy, principal, row and predicate. Also fails when fewer than 20% of cases admit a proper subset of the records, or when the run takes over 60 s. |
| I5 loader | `authz.SharesFor` disagrees with the generator's pair-matched `SharedWith` for 20 callers × every record. Also fails when no caller has a share. |
| I5 mutant `drop_my_groups` / `share_id_only` / `ignore_ops` | The broken compiler agrees on every case: the suite cannot see it. A caught mutant is a PASS row with its first counterexample. |
| I5 data filters | For some caller and filter request, `GET /api/v1/records/iso_et_i5r?filter[...]` (the real handler, `authz.CompileRead` plus the route's filter compiler) returns a record the Go side refuses, or leaves out one it admits. The Go side is `authz.Allows` on the record's row and the side-table oracle (`i5rQuery.matches`) on the record as stored: a value matches only when `record_field_coerce` would copy it (a JSON string for text, a JSON number for num, compared as a double), so an absent key, a JSON `null` and the v1 string `"1"` in `kind` match nothing. GET still serves v2's `prio` default (the run first checks that GET serves the generator's defaulted record). v2's schema backfill never finishes in the run, so the ADR-009 D12 window stays open: a filter that the default satisfies also matches a record whose stored payload has no `prio` key, and does not match one that stores `prio: null` (GET serves it as null). The JSONB scan's absent-default rule went with the scan (ADR-006 D6, TICK-752); the window is its replacement for records not yet rewritten. A filter on `cost` by a caller the mask hides it from must be `400 masked_field`, and no item may carry `cost`. The row reports the count of disagreements by the filtered field's shape and the first one with seed, policy, principal, request and row. Before the flags are published, the run also checks that a filter on each unflagged data field is `400 field_not_filterable` on the list route. It also fails when under 10% of requests match a record, no request is masked, or no match comes only from the window (a `prio` absent as stored). |
| I5 list route | A paged unfiltered list (random sort, limit 4–15, following `next_cursor`) puts a record `Allows` refuses on a page, puts a record on two pages, misses a readable record, or reports a `total` other than the readable count on any page (PR #523 security finding 2). Also fails when under 20% of callers read a proper subset. |
| I5 masked-field oracle | Two twins differ only in `cost`. A caller who reads them with `cost` masked gets one `400 masked_field` body for `filter[cost]` eq and in on either twin's value or neither's, alone or with another filter, and the body never carries the value or a total. Without `cost` in the request the twins are alike: both listed, total 2, items equal but for `id` and `number`, one page each at `limit=1`. Control: a caller the mask admits gets only twin A for `filter[cost]=1`. A fixed case (every user reads, only one user may read `cost`) guarantees both kinds of caller. Fails when either kind is missing. |
| I5 mutant `field_blind` / `absent_matches` | The broken side-table compiler (`server.WithListIndexTerm`, integration builds only) disagrees nowhere the real list route agrees. `field_blind` drops `v.field_id = $n`, so a value of any flagged field of the same value type matches (a `cost` of 1 answers `kind = 1`). `absent_matches` lets a record with no side row for the field (absent, `null`, or a value that does not coerce) match every filter on it, the old absent-default rule widened. Each runs on the first 12 cases. `NAVA_I5_MUTANT=<name>` runs the data filters row against it. |

| I5 format-2 agreement | `TestI5Format2Agreement` (`i5_format2_isolation_test.go`). It fails when, for some random document, principal and record, any of these holds: `CompileRead`'s rows differ from `Allows`; the `ReadBranches` UNION ALL does not return a record `Allows` admits exactly once (with no branch, `ReadPredicate`'s fallback is used); or `Allows` differs from the reference evaluator. It also fails when fewer than 20% of cases admit a proper subset, when no case splits into branches, or when the run takes over 60 s. |
| I5 format-2 caps | A cap case disagrees on any of those sides. It also fails when a policy at a cap compiles to `false` (voided), or when one past a policy cap compiles to anything else. |
| I5 format-1 equivalence (D12) | Each format-1 fixture in `internal/authz/testdata/format1` has its ids remapped onto the world. The row fails when, for some fixture, principal and record, `CompileRead` or `ReadBranches` gives a different row set from the S10 rules. `TestReadBranchesFormat1Golden` (TICK-938, CI-6) covers branch count and SQL text. `TestI5Format1ConvertedMatchesS10` (unit) and the I5 agreement row cover random S10 rule sets. |
| I5 format-2 mutant `not_unguarded` / `invalid_leaf_false` / `ref_previous_version` / `fold_wrong` / `shared_nil_caller` / `under_direct_only` / `under_ignores_tombstone` | The broken compiler agrees with `Allows` on every case, so the suite cannot see it. ### Format-2 mutants: what each breaks and which test catches it

| Mutant | The bug | Guard in the code | Unit test that catches it (`task test`) | Database row that catches it (CI) |
|---|---|---|---|---|
| `not_unguarded` | A uuid `cmp` loses `col IS NOT NULL AND`. `NOT` over a NULL column is then NULL (no row) instead of true. | `plannedCond.sql`, `compiler.colEq` (`internal/authz/plan.go`, `acl.go`) | `TestCompileReadTermsAreTwoValued` (`internal/authz/plan_test.go`) and `TestReadBranchesFormat1Golden` (CI-6 goldens) catch the guard removed from the code. `TestI5Format2MutantsChangeTheSQL` and `TestI5Format2MutantsChangeTheRows` (Kleene model) show the test-side mutant changes the SQL and the rows on the default run. | `I5 format-2 mutant not_unguarded`; also the `depth8` cap case (NOT chain over a nullable `assignee_id`) |
| `invalid_leaf_false` | An invalid node is read as false instead of voiding its policy, so it grants under a `not`. | `planner.node` returns `invalid(...)`; `planner.group` returns the first invalid child (`plan.go`) | `TestI5Format2AllowsMatchesTheReference`, `TestI5ReferenceKnowsD5` | `I5 format-2 mutant invalid_leaf_false`; the reference check of the agreement row |
| `ref_previous_version` | A ref resolves against an older version's conditions. | The planner resolves refs only in the document it plans (`newPlanner`). `PolicyStore` reads policies and conditions from one `acl_versions` row. | `TestI5Format2MutantsChangeTheRows` | `I5 format-2 mutant ref_previous_version` |
| `fold_wrong` | The caller-only fold of `member_of` is inverted. | `planner.node`, `NodeMemberOf` (`plan.go`) | `TestI5Format2AllowsMatchesTheReference`, `TestI5Format1ConvertedMatchesS10`, `TestI5ReferenceKnowsD5` | `I5 format-2 mutant fold_wrong`; the reference check of the agreement row |
| `shared_nil_caller` | `shared` holds for a caller with no id through its groups' shares. | `planner.node`, `NodeShared` nil-caller fold (`plan.go`) | `TestI5Format2AllowsMatchesTheReference` (the last of its 4 principals is always a caller with no id but with groups, with the record's group shares in its row) and `TestI5ReferenceKnowsD5` | `I5 format-2 mutant shared_nil_caller` |

| `under_ignores_tombstone` | The leaf walks `org_units` without reading `deleted_at`, so tombstoned units stay in the region, and so does a live unit below one: access through a unit removed from the directory survives the sync. | The closure holds live paths only (`org_unit_closure_rebuild_all`, group sync) | `TestI5Format2MutantsChangeTheRows`, `TestI5UnderMutantsCaughtAcrossSeeds` | `I5 format-2 mutant under_ignores_tombstone`; `TestOrgUnitRemovalEndsUnderAccessAndSyncSucceeds` (`internal/groupsync`) end to end |

When a guard in `plan.go` is reverted, `Allows` and `CompileRead` move together, and only the reference comparison sees it. Verified on 2026-11-19: reverting the `fold_wrong`, `invalid_leaf_false` and `shared_nil_caller` guards one at a time turned the unit tests above red. Removing the `IS NOT NULL` guard turns `TestCompileReadTermsAreTwoValued` and `TestReadBranchesFormat1Golden` red (PR #772 review). Removing the duplicate-name guard (`pl.dup`) also turned `TestI5Format2AllowsMatchesTheReference` red.

## Risks, ranked, and the layer that covers each

1. **SQL admits a row Go refuses, or the reverse** (wrong list or wrong 404). Covered by the agreement row (testcontainers-style real PostgreSQL, under RLS as `nava_app`).
2. **Shares matched by id alone** (AR-S10-01). Covered by the decoy shares in the agreement row, the `share_id_only` mutant and the loader row.
3. **A NULL fixed column matched by a condition.** Covered by the NULL columns in the agreement row.
4. **Malformed rules handled differently on the two sides.** Covered by the malformed conditions in the agreement row.
5. **A suite too weak to fail.** Covered by the mutant rows, the proper-subset guard, and `TestI5GeneratorCoversTheRiskyShapes` / `TestI5MutantsChangeTheSQL` (unit tests).
6. **A data filter that matches stored data while the read serves defaults** (a row written before a default existed is shown with the default and missed by a filter on it). Since TICK-752 this is the specified behaviour, not a bug: a data filter reads the side table, which holds stored values only (ADR-006 D6), while GET serves the defaults. The data filters row pins it: the list must leave such a record out, the row fails if the run has none, and the `absent_matches` mutant (which would match it) must be caught.
7. **Type confusion and nulls in data filters** (a v1 string matching an integer filter, a `null` matching). Covered by the data filters row (the side table copies neither) and the `absent_matches` mutant. A value of another flagged field read for this one is the `field_blind` mutant.
8. **A list that leaks an unreadable record or counts one** (a page, a cursor or `total`). Covered by the list route row.
9. **Masked fields used as an oracle** (filter, total, paging). Covered by the masked-field row and S10 attack row 3. `TestI5RouteGeneratorCoversTheRiskyShapes` (unit) fails when the default seed's route run lacks any of the five field shapes, a v1 row that reads v2's default, a filter on that default, eq or in, callers on either side of the mask, or a stored value the side table copies for each flagged field.
10. **A format-2 planner bug that moves both renderings** (`Allows` and `CompileRead` share one plan). Covered by the reference evaluator in the format-2 agreement row, and by `TestI5Format2AllowsMatchesTheReference` (unit).
11. **The D5 failure modes:** NOT over a three-valued term, an invalid node read as false, a ref resolved against the wrong version, a caller fold inverted, and `shared` holding for a caller with no id. Covered by the five D5 format-2 mutant rows (table above).
14. **`under` grants a record outside the live subtree, or misses one inside it** (D7): descendants dropped, a tombstoned unit or a live unit below one kept, a NULL `org_unit_id` matched. Covered by the format-2 agreement row (reference `i5Subtree` over random trees, the seeded closure read through `ResolveUnder` and the C1 leaf checked against it for every principal), the two `under` mutant rows, and `TestI5OrgTreeIsRandomAndRisky` / `TestI5UnderMutantsCaughtAcrossSeeds` (unit).
15. **A unit removed from the directory fails the sync or keeps granting** (S31 criterion 3). Covered by `TestOrgUnitRemovalEndsUnderAccessAndSyncSucceeds` (`internal/groupsync`, integration): records still name a unit when it goes, the sync succeeds, the records keep `org_unit_id`, and `under` caller and `under` [unit] stop admitting them, in the list predicate and in `Allows`; then the caller's own unit goes and its access stops.
12. **A converted format-1 policy that grants something other than S10 did** (D12). Covered by the format-1 equivalence row, `TestI5Format1ConvertedMatchesS10` and `TestReadBranchesFormat1Golden`.
13. **A policy at a cap that plans differently, or a cap that does not void.** Covered by the format-2 caps row and `TestI5Format2CapCasesPlanAsTheCapsSay`.

## Not tested here, and why

- **Write agreement.** `CompileRead` is read only. Write is the Go check alone (`CanWrite`), and `internal/records/pipeline/acl_integration_test.go` covers it.
- **Cross-tenant ids in a policy.** The publish route rejects them (P3-35), and the Security & Multi-Tenancy Reviewer owns that review.
- **Nested data properties, arrays, unions and objects.** The route has no filter on them (`filterValue` refuses them), so there is nothing to agree on.
- **Shares that cross kinds in the route world.** `record_shares` has foreign keys, so a decoy share cannot be stored; the SQL agreement row covers the pair-matched rule with decoys.
- **Malformed rules on the route.** `acl_versions`' shape CHECK refuses them, so the route can never read one; the SQL agreement row covers them.
- **`under` speed.** The region bench covers it (`docs/quality/acl-perf-region.md`, S31 rerun).
- **`under` regions over 10,000 units.** There is no cap since TICK-1034; the random trees hold at most 40 units, and `TestUnderAboveTenThousandUnitsIsANormalAnswer` (`internal/records/pipeline`, integration) covers a region of 10,002 units and its capped count.
- **Documents past the document caps** (65 policies, 129 document leaves). The planner does not enforce document caps, by design. Publish (`Prepare`, TICK-939) and the database CHECK (TICK-940) refuse such documents, and their tests cover it.
- **Performance of format-2 predicates.** The SP-2 benchmarks cover it (`docs/data/acl-format2-caps.md`).

## Commands

- Unit tests: `task test`. They cover the generators, determinism, the reference evaluator against `Allows`, format 1 against S10, and the cap cases. They also check that each mutant changes the SQL and the admitted rows.
- Database half: the `integration` job of the GitHub `ci` workflow (`make isolation`). Read the `isolation-report` artifact. Agents never run it locally.
- Replay a seed: `NAVA_I5_SEED=<n> make isolation`. The seed is logged on every run and printed in a failing row.
- Mutation run: `NAVA_I5_MUTANT=drop_my_groups make isolation` turns the agreement row red. `NAVA_I5_MUTANT=field_blind make isolation` (or `absent_matches`) runs the data filters row against that broken list route and turns it red. `NAVA_I5_MUTANT=<format-2 mutant> make isolation` turns the format-2 agreement row red. The format-2 mutants are `not_unguarded`, `invalid_leaf_false`, `ref_previous_version`, `fold_wrong`, `shared_nil_caller`, `under_direct_only` and `under_ignores_tombstone`.
